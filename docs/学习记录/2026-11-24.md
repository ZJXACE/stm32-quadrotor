## 二、今天真正学会的东西

### 1. IP5305T 为什么要"喂"它——脉冲保持

IP5305T 是移动电源（充电宝）管理芯片，它有个特性：**如果一段时间收不到按键动作，就认为没人用，自动切断输出**。

所以单片机要假装自己"一直在按按钮"：定时把 `POWER_KEY` 拉低 100ms 再拉高，芯片就认为按键还活着，继续供电。

```c
void Int_IP5305T_Start(void)
{
    HAL_GPIO_WritePin(POWER_KEY_GPIO_Port, POWER_KEY_Pin, GPIO_PIN_RESET); // 拉低 = 按下
    vTaskDelay(100);                                                       // 按住 100ms
    HAL_GPIO_WritePin(POWER_KEY_GPIO_Port, POWER_KEY_Pin, GPIO_PIN_SET);   // 松开
}
```

**关键点**：这个"喂电"动作绝对不能迟到。一旦这个任务被高优先级任务长时间抢占、错过了时间窗，芯片直接断电——整机重启。这就是为什么它的优先级必须最高。

### 2. `vTaskDelay` vs `vTaskDelayUntil`：差在"从哪开始数"

| | `vTaskDelay(900)` | `vTaskDelayUntil(&x, 900)` |
| --- | --- | --- |
| 从什么时候开始数 | 从现在开始（任务干完活之后才数） | 从上次醒来的那一刻开始 |
| 实际周期 | 900ms + 任务本身执行时间 | 严格 900ms |
| 误差 | 每轮累积，越积越多 | 不会累积 |

电源保持要的是**绝对等间隔**，所以必须用 `vTaskDelayUntil`。

### 3. tick 是什么：`configTICK_RATE_HZ = 1000` → 1 tick = 1ms

推导过程（这是今天追问出来的）：

1. `HZ` 的意思就是"每秒多少次"
2. `configTICK_RATE_HZ = 1000` 就是"每秒 1000 个节拍"
3. 所以 1 个节拍 = 1/1000 秒 = **1ms**

于是 `vTaskDelayUntil(&x, 10000)` = 10000 × 1ms = **10 秒**，`vTaskDelayUntil(&x, 6)` = **6 毫秒**。

> 这里有个陷阱：如果 `configTICK_RATE_HZ` 改成 100，那 10000 就变成 100 秒了。**换算永远要回来看这个宏。**

### 4. 为什么 `task.h` 前面必须先 `#include "FreeRTOS.h"`

不是"建议"，是**硬门槛**。`task.h` 开头就有：

```c
#ifndef INC_FREERTOS_H
    #error "include FreeRTOS.h must appear in source files before include task.h"
#endif
```

不先包含 `FreeRTOS.h`，编译器直接停在 `#error`。原因很简单：`task.h` 里用到的类型（`TickType_t`、`BaseType_t`、`portTickType`...）全在 `FreeRTOS.h` 里定义。

### 5. PWM 的三个参数：PSC 定"多快"，ARR 定"数多少格"，CCR 定"高电平占几格"

我自己总结的一句话：

> 时钟频率决定 count 每次加 1 的速度，ARR 决定一个周期要数多少格，CCR 决定这格里高电平占几格。

套到今天的具体配置：

```
计数时钟 = 72MHz ÷ 4（PSC=4-1） = 18MHz   → count 每 55.5ns 加 1
ARR      = 1000-1                          → 一轮数 1000 格
PWM 频率 = 18MHz ÷ 1000 = 18kHz             → 周期 55.55μs
CCR      = 200                             → 占空比 200/1000 = 20%
```

三个参数各管一件事，互不混淆：**改 PSC/ARR 动频率，改 CCR 动占空比。**

### 6. 用结构体把"一个电机"抽象出来

以前写代码是"要用哪个定时器就直接写死 `&htim3`、`TIM_CHANNEL_1`"。今天第一次主动做抽象：

```c
typedef struct
{
    TIM_HandleTypeDef *htim;   // 哪个定时器
    uint16_t channel;          // 哪个通道
    uint8_t speed;             // 当前速度（= CCR 值）
} Motor_Struct;

Motor_Struct LEFT_0_motor = { .htim = &htim3, .channel = TIM_CHANNEL_1, .speed = 200 };
```

这样函数只要收一个指针，就能操作任意一个电机：

```c
void Int_Motor_SetSpeed(Motor_Struct *motor) { __HAL_TIM_SetCompare(motor->htim, motor->channel, motor->speed); }
void Int_Motor_Start(Motor_Struct *motor)    { HAL_TIM_PWM_Start(motor->htim, motor->channel); }
```

**这就是"数据 + 操作"绑在一起的雏形**，四个电机共用一套代码，不用写四遍。

### 7. 为什么要分层：Application / Interface / Common

```
Application  ← 业务逻辑（建哪些任务、周期多少、任务里干什么）
Interface    ← 硬件接口（Int_Motor 电机、Int_IP5305T 电源芯片）
Common       ← 公共工具（Com_debug 串口打印）
Core         ← CubeMX 生成的外设初始化（main.c / tim.c / gpio.c / usart.c）
```

好处：以后换电机驱动芯片、换电源芯片，只改 `Interface` 层；上层任务代码一行不动。

## 三、学习感悟

1. **今天的分水岭是"开始设计结构，而不是堆代码"**。前几天的代码是把 CubeMX 生成的函数一个个调过去；今天第一次自己定义结构体、自己划分层次、自己决定任务周期。写代码的思维方式开始从"能跑就行"转向"以后要改怎么办"。

2. **追问"为什么"比记住"是什么"值钱**。今天花时间追问"为什么 1000 就是 1ms"，看起来慢，但从此以后看到任何 `vTaskDelay(x)` 都能自己换算，不用再问人。

3. **优先级是一个设计决策，不是随手填的数字**。电源保持任务必须最高——这个结论是从"断电会怎样"倒推出来的，不是从例程抄的。以后填优先级，先问自己："这个任务迟到了会有什么后果？"

4. **编译报错是好事，红色波浪线是免费的老师**。今天两处 HAL 函数名大小写错误、一处 `time.h`/`tim.h`，全是编译器先发现的。看懂报错比背 API 有用。

5. **魔法数字是技术债**。`vTaskDelayUntil(&x, 10000)` 里的 10000，三个月后自己都不记得是 10 秒。改成 `POWER_task_period` 只花 10 秒，省下的可能是半小时。

## 四、踩坑记录

| # | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | Keil 报错找不到 `htim1`/`htim3`，但明明"引入了头文件" | 写成了 `#include "time.h"`（C 标准库的时间函数），不是 CubeMX 生成的 `tim.h` | 改成 `#include "tim.h"`。**`time.h` 和 `tim.h` 差一个字母，完全两回事** |
| 2 | `HAL_TIM_set_compare` 下方红线，提示未定义 | HAL 的函数名是全大写的 `HAL_TIM_PWM_Start`，改比较值则是宏 `__HAL_TIM_SetCompare`（两个下划线 + 驼峰） | 启动用 `HAL_TIM_PWM_Start()`，设占空比用 `__HAL_TIM_SetCompare()` |
| 3 | `hal_tim_pwm_start` 全小写，编译报未定义 | C 语言区分大小写，HAL 库的函数名是 `HAL_TIM_PWM_Start` | 严格按 HAL 命名规范写，靠 IDE 的自动补全别手敲 |
| 4 | 任务周期直接写 `10000`，可读性差 | 魔法数字，看代码不知道单位 | 定义 `#define POWER_task_period 10000` 并注释"10s" |
| 5 | 电源任务被别的任务抢占，出现过断电感 | 优先级设低了（或和业务任务同级） | 电源保持任务优先级设为最高（本项目 = 4） |
| 6 | 定时器通道配了 PWM 却不出波形 | 定时器的 `Clock Source` 没选 `Internal Clock` | CubeMX 里 Clock Source 选 **Internal Clock**，否则计数器没有时钟 |
| 7 | `Motor_Struct.speed` 注释写"最大 1000"，实际却到不了 | 成员类型是 `uint8_t`（最大 255），`if (motor->speed > 1000)` 这个判断永远不成立（无符号 8 位不可能大于 1000），编译器可能直接优化掉 | 改成 `uint16_t`，并让 PWM 的 ARR（1000）与速度上限对得上 |
| 8 | 四路电机转起来转速/响声不一致 | TIM3 的 Prescaler 是 0，另外三个是 `4-1` → TIM3 是 72kHz，其余是 18kHz | CubeMX 里把 TIM3 的 Prescaler 也设成 `4-1`，四路频率统一 |

> 另外两个"小坑"是代码规范层面的：`Int_Motor.h` 的头文件保护写成了 `#ifndef __INT_MOTOR_H__` + `#define __INT_MOTOR_H_`（少一个下划线，保护实际失效）；头文件里的中文注释偶尔会被编辑器存成 GBK/乱码，后来加了 `.editorconfig` 强制 UTF-8。
