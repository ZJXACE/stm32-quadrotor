## 今天的目标

遥控器上除了摇杆，还有 6 个独立按键，今天把它们接进来：

| 按键 | 位置 | 以后的功能（规划） |
| --- | --- | --- |
| `KEY_UP` | 上 | 菜单上翻 |
| `KEY_DOWN` | 下 | 菜单下翻 |
| `KEY_LEFT` | 左 | 左移 |
| `KEY_RIGHT` | 右 | 右移 |
| `KEY_LEFT_X` | 左上 | 短按**关机** |
| `KEY_RIGHT_X` | 右上 | 短按**定高**、长按**校准摇杆** |

所以要区分三种结果：短按、长按、没按。

## 一、驱动设计：一个按键要经过 4 步才算"真的按下"

```c
KEY_type Int_Key_Get(void)   /* 返回这个周期内被按下的键，没有则返回 KEY_NONE */
```

每个按键分支都是同一套四步：

| 步 | 代码 | 为什么 |
| --- | --- | --- |
| 1 | `HAL_GPIO_ReadPin(...) == GPIO_PIN_RESET` | 按键低有效（内部上拉，按下接地） |
| 2 | `vTaskDelay(5);` 再读一次 | **消抖**：机械触点按下瞬间会抖 5~10ms |
| 3 | `while(仍然按下);` | **等抬起**：否则一次按下会被扫描到十几次，打印/指令连发 |
| 4 | `return KEY_xxx;` | 抬起后返回"哪个键" |

> 第 3 步是"边沿触发"：**按下→抬起，才算一次**。这样上层每收到一次返回值，就对应你的一次真实按键动作。

## 二、长按怎么判：打两个时间点，算差值

```c
else if (KEY_RIGHT_X 按下)
{
    TickType_t Count1 = xTaskGetTickCount();   /* ① 按下瞬间打点 */
    vTaskDelay(5);                             /* ② 消抖 */
    if (仍然按下)
    {
        while (仍然按下) { vTaskDelay(1); }    /* ③ 按住不放，每 1ms 让一次 CPU */
        TickType_t Count2 = xTaskGetTickCount();   /* ④ 抬起瞬间打点 */
        if (Count2 - Count1 > 1000)  return KEY_RIGHT_X_LONG;   /*   >1s 长按 */
        else                         return KEY_RIGHT_X;        /*   否则短按 */
    }
}
```

关键点：`Count1` 在**按下时**记，`Count2` 在**抬起时**记，差值就是"按了多久"。

## 三、踩坑：少一个 `}`，3 个按键直接"消失"

### 现象

| 按键 | 打印 |
| --- | --- |
| 上 / 下 / 左 / 右（1~4） | ✅ 正常 |
| 左上（5）、右上（6/8） | ❌ **按了完全没反应**，不打印 |

### 原因：`else if` 挂到了错误的 `if` 上

当时 `KEY_RIGHT` 那个分支**少写了一个 `}`**：

```c
else if (KEY_RIGHT 按下)
{
    vTaskDelay(5);
    if (KEY_RIGHT 仍然按下)
    {
        while (...);
        return KEY_RIGHT;
    }                    /* ← 这里只关了"内层 if" */
                         /* ← 少了关闭"外层 else if"的 } */
    else if (KEY_LEFT_X 按下)     /* 变成了内层 if 的 else */
    {
        ...
        return KEY_LEFT_X;
    }
}                        /* 到函数末尾才关掉外层 */
```

C 语言的规则是 **`else` 就近匹配**，所以那两个 `else if` 成了"右方向键那个 `if` 的 else"：

> **只有按住右方向键时，才会去检查左上 / 右上。**

按别的键时外层 `else if (KEY_RIGHT ...)` 不成立，整块跳过 → 直接走到 `return KEY_NONE`。

更坑的是：**编译器不报错、不警告**（花括号是配平的，只是位置错了），只能靠"哪几个分支走不到"去推。

### 修复

| 改动 | 内容 |
| --- | --- |
| ① | 在 `//左上按键` 前面补一个 `}`，关掉 `KEY_RIGHT` 的 `else if` 块 |
| ② | 删掉函数末尾多出来的那个 `}` |

改完用花括号深度逐行核对：函数体深度应在 `1`，每个 `else if` 进出后回到 `1`，结束回到 `0`。

## 六、晚上补充：搭 `remote` 数据通路（按键 → 数据包 → 发送）

### 1. 目标

把"按键/摇杆"和"发送"串起来：按键改变状态，发送任务把状态打包发给飞机。

```
按键任务 ──► App_Process_KeyData() ──► remote.Shutdown = 1
                                          │
                                     （共享结构体）
                                          ▼
发送任务 ──► 读 remote ──► 打包 32 字节 ──► Int_SI24R1_TxPacket()
```

### 2. 设计：用一个结构体当"中转箱"

`APP_process_data.h`：

```c
typedef struct {
    uint16_t thr;          /* 油门 */
    uint16_t yaw;          /* 偏航 */
    uint16_t pitch;        /* 俯仰 */
    uint16_t roll;         /* 滚转 */
    uint8_t  Shutdown;     /* 0 不关机 / 1 关机 */
    uint16_t Fix_Height;   /* 定高 */
} Remote_Data;

extern Remote_Data remote;      /* 供所有 .c 引用 */

extern int16_t key_pitch_offset;  /* 俯仰微调 */
extern int16_t key_roll_offset;   /* 滚转微调 */
```

`APP_process_data.c` 里只定义一次：

```c
Remote_Data remote = {0};
int16_t key_pitch_offset = 0;
int16_t key_roll_offset  = 0;
```

### 3. 今天修掉的 4 个错（全部是"定义/声明"问题）

| # | 报错 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | `未定义标识符 key_pitch_offset` | 头文件没有 `extern` | 头文件加声明 |
| 2 | `147 declaration is incompatible` | `.h` 用 `uint16_t`，`.c` 用 `int16_t` | 统一 `int16_t` |
| 3 | `L6218E Undefined symbol Shutdown` | 给结构体成员写了 `extern` | 改成 `remote.Shutdown` |
| 4 | `identifier Remote_Data is undefined` | `extern Remote_Data remote;` 写在结构体**前面** | 挪到 `}Remote_Data;` 之后 |

详细原理见 [学习记录/2026-11-27 第八节](../学习记录/2026-11-27.md)。
