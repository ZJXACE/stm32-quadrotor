## 今天的目标

昨天做到"飞控能收到遥控器发的 `hilowr`"，但那只证明**单向通**。今天要把它变成真正的双向：

1. 遥控端（P02）自己也能发，并且打印每次发送的结果
2. 飞控端（P01）只负责收，别再每圈重配
3. **`TX ret=0`** 才算双向打通（对端芯片回了 ACK）
4. 收完数据还要能讲清楚这两个函数每一行在干什么

## 一、遥控端 P02：从零把 Si24R1 接进来

### 1. CubeMX 配置

| 项目 | 配置 |
| --- | --- |
| SPI1 | 主机、2 线全双工、模式 0、MSB 先发、72MHz ÷ 8 = **9 MHz** |
| 引脚 | **PB3 = SCK / PB4 = MISO / PB5 = MOSI**（SPI1 **重映射**，`__HAL_AFIO_REMAP_SPI1_ENABLE()`） |
| CSN | **PA15**（`SPI1_NSS`，软件控制） |
| CE | **PB7**（`SP_EN`） |
| IRQ | 不接（驱动走轮询） |

注意：P01 用的是 PA5/PA6/PA7 + CSN=PA4 + CE=PA8，**两块板的引脚完全不同**，但芯片看到的 SPI 时序是一样的。

### 2. 驱动移植

把 P01 的 `Int_SI24R1.c/.h` 整份复制到 P02，只改四件事：

- `CS_LOW/CS_HIGH` 里的端口引脚（CSN：PA4 → PA15）
- `CE_LOW/CE_HIGH`（CE：PA8 → PB7）
- P02 的 `hspi1` 句柄
- 保留 `TX_PLOAD_WIDTH = 32`、地址、频道、`RF_SETUP = 0x06` 不动

### 3. 通信任务改成"发"

```c
void Comm_Task(void *pvParameters)
{
    portTickType lastWakeTime = xTaskGetTickCount();
    while (1)
    {
        Int_SI24R1_TX_Mode();                 // 1. 先切发送模式

        Com_buff[0] = 'h';  Com_buff[1] = 'i';  Com_buff[2] = 'l';
        Com_buff[3] = 'o';  Com_buff[4] = 'w';  Com_buff[5] = 'r';

        uint8_t r = Int_SI24R1_TxPacket(Com_buff);
        Debug_Printf("TX ret=%d\r\n", r);     // 0=对方回ACK 1=重发超限 2=超时

        Int_SI24R1_RX_Mode();                 // 2. 发完切回接收
        vTaskDelayUntil(&lastWakeTime, COMM_PERIOD);   // 6ms
    }
}
```

`ret` 的三种取值就是排查的三条线索：

| 返回 | 含义 | 说明 |
| --- | --- | --- |
| `0` | `TX_DS` 置位 | **对端芯片回了 ACK** —— 双向通的最强证据 |
| `1` | `MAX_RT` 置位 | 对端没应答，重发次数用完（地址/频道/速率不一致，或对端没上电） |
| `2` | 20ms 超时 | 射频可能根本没工作（SPI 通但 16MHz 晶体/PA 坏了也会这样） |

## 二、飞控端 P01：做减法

昨天的写法是"每圈 `RX_Mode()` 再 `RxPacket()`"，今天删掉前者：

```c
void Comm_Task(void *pvParameters)
{
    portTickType lastWakeTime = xTaskGetTickCount();
    while (1)
    {
        uint8_t res = Int_SI24R1_RxPacket(Com_buff);

        static uint16_t cnt = 0;
        if (++cnt % 166 == 0) Debug_Printf("waiting...\r\n");   // 约 1 秒一次心跳

        if (res == 0)
        {
            Debug_Printf("RX: %c%c%c%c%c%c\r\n",
                         Com_buff[0], Com_buff[1], Com_buff[2],
                         Com_buff[3], Com_buff[4], Com_buff[5]);
        }

        // Int_SI24R1_RX_Mode();   // 不能说：RX_Mode 只由 Init 调一次
        vTaskDelayUntil(&lastWakeTime, COMM_PERIOD);            // 6ms
    }
}
```

**为什么必须删**：`RX_Mode()` 内部会 `Write_Reg(STATUS, 0xFF)` 把所有中断标志清掉——包括刚收到的 `RX_DR`。每圈都调，等于"每 6ms 自己把收到的证据擦掉一次"，表现就是"明明有信号却永远读不出来"。

## 三、两端参数逐字节对齐（今天通的关键）

| 参数 | 值 | 在哪 |
| --- | --- | --- |
| 地址 | `0A 01 08 0E 01` | `TX_ADDRESS` / `RX_ADDRESS` |
| 频道 | `40`（2440 MHz） | `RF_CH` |
| 速率 / 功率 | 1 Mbps / +4 dBm | `RF_SETUP = 0x06` |
| 负载长度 | 32 字节 | `TX_PLOAD_WIDTH` |
| 地址宽度 | 5 字节 | `TX_ADR_WIDTH` |

昨天踩过的坑在这里复现不了第二遍：**两块板只要有一项不一致，现象就是"完全收不到"**，看起来像硬件坏了。

## 四、实测结果

| 观察点 | 结果 |
| --- | --- |
| P02 串口 | `TX ret=0` 占绝大多数（偶尔 1） |
| P01 串口 | 稳定打印 `RX: hilowr`，穿插 `waiting...` 心跳 |
| 丢包 | 约 **10%**（6ms 周期） |

结论：**双向链路打通**。`ret=0` 说明飞控端的芯片真的回了 ACK，这比"飞控收到了"更强——它证明对端的射频、地址、频道全部在工作。

## 六、晚上：把两个收发函数逐行拆开

晚上没写代码，把 `RxPacket` / `TxPacket` 从头到尾问了一遍。四张"底牌"：

### 1. `SPI_RW()` 的"附赠品"是 STATUS

只要 CSN 拉低，**第一个字节交换**就是"我发命令 + 芯片同时吐出 STATUS"。所以：

```c
/* 写寄存器：这次 STATUS 顺手接住 */
status = SPI_RW(reg);   // 发写命令，收下 STATUS
SPI_RW(value);          // 发数据

/* 读寄存器：这次 STATUS 直接丢掉 */
SPI_RW(reg);            // 命令发出去，STATUS 回来但不要
value = SPI_RW(0);      // 发 dummy，拿到寄存器真数据
```

作者在写寄存器时接、读寄存器时不接，是**取舍**不是规定：写的时候后面常要立刻判断芯片状态；读的时候目标只是寄存器值，而且真读 `STATUS` 时第二次交换还会再给一遍。

### 2. `RxPacket`：读 → 清 → 判 → 取 → 冲

```c
uint8_t Int_SI24R1_RxPacket(uint8_t *rxbuf)
{
    uint8_t state;
    state = Int_SI24R1_Read_Reg(STATUS);                 // ① 看有没有 RX_DR
    Int_SI24R1_Write_Reg(SI24R1_WRITE_REG + STATUS, state); // ② 原样写回 = 写 1 清零

    if(state & RX_DR)                                    // ③ 确实收到了
    {
        Int_SI24R1_Read_Buf(RD_RX_PLOAD, rxbuf, TX_PLOAD_WIDTH); // ④ 读 32 字节
        Int_SI24R1_Write_Reg(FLUSH_RX, 0xff);            // ⑤ 冲掉 RX FIFO
        return 0;
    }
    return 1;                                            // 没数据
}
```

`rxbuf` 不是函数里 new 出来的，是**调用者提前准备好的数组**，函数只负责把芯片里的包填进去。

### 3. `TxPacket`：CE 低 → 写 → CE 高 → 等 → 清

```c
CE_LOW;                                                   // 射频关，才能安全写 FIFO
Int_SI24R1_Write_Buf(WR_TX_PLOAD, txbuf, 32);             // 塞 32 字节
CE_HIGH;                                                  // 射频开，开始发
while((state & TX_DS) == 0 && (state & MAX_RT) == 0)      // 既没成也没败，就读
    state = Int_SI24R1_Read_Reg(STATUS);
Int_SI24R1_Write_Reg(SI24R1_WRITE_REG + STATUS, state);   // 清标志
```

`while` 的条件翻译成人话：**"成了"或"败了"任意一个发生就退出**。这正是"轮询"——CPU 主动反复问芯片"发完没"，等待期间什么都干不了（这也是后面要上 IRQ 的原因）。

### 4. CE 是射频总开关，不是"抢话筒"

| CE | 状态 | 能干什么 |
| --- | --- | --- |
| 低 | Standby / 配置 | 通过 SPI 写 FIFO、改寄存器 |
| 高 | 发射 / 接收 | 射频电路工作，至少保持 10µs 才真正启动 |

所以发一包的固定流程是"**拉低 CE → 写数据 → 拉高 CE**"；而**读 RX FIFO 不用动 CE**，那只是 SPI 读操作，靠 CSN 就够了。

### 5. 顺带把状态机看懂了

`Power Down ⇄ Standby ⇄ Idle-TX ⇄ TX`，两条关键边：

- `TX FIFO 有数据 且 CE=1` → 进 TX（切换时间 **120~130µs**，所以 CE 拉高后不能马上以为发完了）
- `单帧发完 且 CE=0` → 回 Standby
