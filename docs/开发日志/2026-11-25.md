## 今天的目标

把四个 LED 从"能亮"做成一套能表达状态的指示灯。

## 今天做了什么

1. **CubeMX 加四路 LED 输出**（初始高电平，低电平点亮）
   | 名字 | 引脚 | 位置 |
   | --- | --- | --- |
   | LED1 / LEFT_TOP | PA12 | 左上 |
   | LED2 / RIGHT_TOP | PA11 | 右上 |
   | LED3 / RIGHT_BOTTOM | PB15 | 右下 |
   | LED4 / LEFT_BOTTOM | PB14 | 左下 |
2. **新增 `Interface/Int_Led.c/.h`**：`Led_Struct` 封装「端口 + 引脚」，提供 `Int_led_on / off / toggle` 三个接口
3. **新增 `Common/Com_config.h`**：集中定义两个状态枚举
   - `RemoteControl_Status`：连接 / 断开
   - `Plane_Status`：空闲 / 飞行 / 定高 / 错误
4. **`Int_Led_Task` 写成状态机**
   - 前两个灯：遥控已连接 → 常亮；未连接 → 熄灭
   - 后两个灯：按飞行状态切换灯效（空闲慢闪 500ms、飞行快闪 200ms、定高常亮、错误熄灭）
   - 统一 100ms 节拍，用 `Count` 取余做"软件分频"

## 设计上值得记住的三点

1. **灯是"对象"不是"引脚"**：`Led_Struct` 让函数只认"哪盏灯"，不关心它接在哪个引脚
2. **灯效是"状态"驱动的**：状态变了灯才变，而不是写一堆 `vTaskDelay` 硬等
3. **一个任务管四盏灯**：用统一节拍 + 取余分频，而不是为每盏灯建一个任务或延时节拍

## 遗留问题

- `remote_control_status` 目前写死为 `REMOTE_CONTROL_CONNECTED`（为了调试时能看到两个灯亮），等遥控链路做好要改成由通信任务写入
- `plane_state` 初值是 `Error`，所以上电后后两个灯是**熄灭**的（不是坏了）
- `if / else if` 链最后没有 `else` 兜底，状态值异常时灯效会"保持上一次"

## 晚上收尾：下载故障、重试自检、超时保护（21:00~22:10）

### 1. 下载失败与排查（21:47）

现象：Keil 下载报

```
Erase Done. Cannot Write to RAM for Flash Algorithms !
Programming Failed! Error: Flash Download failed - "Cortex-M3"
```

排查顺序（最后确认是连接/速度层，不是代码问题）：

| 检查 | 结果 |
| --- | --- |
| 工程 Flash/RAM 配置（0x08000000/64K、0x20000000/20K） | ✅ 正常 |
| 烧写算法 `STM32F10x_128.FLM`、算法 RAM 0x20000000/2K | ✅ 正常 |
| **ST-Link 速度 10MHz → 改 1.8MHz** | ✅ 解决 |
| 板子独立供电（不只靠 ST-Link） | ✅ 同时改进 |

**结论**：`Cannot Write to RAM for Flash Algorithms` 多半是 **SWD 速度太高 / 供电不足**，不是工程配置。

### 2. 一次认知纠正：不存在"必须先读一次"

之前观察"必须上电先读一次 SPI 才能写"，一度以为芯片要求"预热"。下载问题解决后复测：**延时和首帧读取都不需要**。

真实原因是**首帧在芯片未就绪/片选时序不对/下载失败期间本身就不可靠**——它是症状，不是芯片要求。

顺带更正：网上流传的"上电必须先读一次"属于**经验做法（丢弃坏的首帧）**，不是手册规定。手册只要求：
- 上电后延时 100ms（**P6**）
- 写寄存器前 CE=0（**P14**）
- CSN 从高到低才算一帧开始（**P14**）

### 3. `Int_SI24R1_Init` 改成"重试自检"

```c
uint8_t Int_SI24R1_Check(void)      /* 写地址 → 读回 → 逐字节比对，0=一致 */
void    Int_SI24R1_Init(void)       /* while(Check()!=0){HAL_Delay(10);} 通过后 RX_Mode() */
```

比固定延时好在：

- 通了立刻继续（最快 10ms），不用盲等 100/200ms
- 首帧不可靠时**自动重试**，不用再靠"先读一次"兜底
- 自检通过后打印 `SI24R1 Init Success`，并**默认进入接收模式**

### 4. `TxPacket` 超时保护

- 原来：`while(IRQ==1)` 死等（IRQ 还没接线 → 必然卡死）
- 改为：轮询 `STATUS` 的 `TX_DS/MAX_RT`，**`HAL_GetTick()` 20ms 超时**
- 超时处理：`FLUSH_TX` 清残留包 → 走原有失败出口 `return 1`
