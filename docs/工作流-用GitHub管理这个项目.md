# 和我一起用 GitHub 的日常流程

这份文档是给我（以及未来的我）看的操作手册：**每天怎么存档，遇到问题怎么回退，怎么让 AI 助手代劳。**

## 一、Git 到底在管什么

三个地方，别搞混：

| 位置 | 是什么 | 命令 |
| --- | --- | --- |
| 工作区 | 你电脑上正在改的文件 | 直接编辑 |
| 本地仓库 | 你电脑上的"存档点"（`.git` 目录） | `git add` → `git commit` |
| 远程仓库 | GitHub 上的那份备份 | `git push` |

- **commit（提交）** = 给当前所有改动拍一张快照，附一句说明
- **push（推送）** = 把本地的快照上传到 GitHub
- 有了这两步，**代码永远丢不了**，而且能回到任何一天的状态

## 二、每天的标准动作

```
改代码 → 编译通过 → 让 AI 写日志 → commit → push
```

对 AI 助手说这一句就够了：

> **"存档今天的进展：今天做了 XXX，学会了 XXX"**

我会自动完成：`git status` 看改动 → 写/更新当天开发日志 → `git add` → `git commit`（规范的提交信息）→ `git push`，并告诉你这次提交改了什么。

## 三、可以让我做的事（照着说就行）

| 你想干的事 | 怎么说 |
| --- | --- |
| 存档今天的进展 | "存档今天的进展：……" |
| 看今天改了哪些文件 | "看看我改了啥 / 给我看 diff" |
| 提交说明不知道写啥 | "帮我看看这次提交说明怎么写" |
| 写今天的学习笔记 | "帮我写今天的开发日志" |
| 代码改坏了想回退 | "回退到上一次提交" |
| 想试试新功能又怕搞坏 | "开个分支做 XXX" |
| 整理 README / 进度勾选 | "更新 README 的进度" |
| 发布一个版本 | "给现在这个版本打 tag v0.1" |
| 想把代码放私有 | "把仓库改成私有" |

## 四、我给 AI 的"安全规则"

1. **只在项目根目录 `四轴无人机项目/` 内操作**，不碰桌面其他东西
2. **绝不提交密码、密钥、WiFi 密码**（`.gitignore` 已排除常见产物，但密钥要自己留意）
3. 提交前必须 `git status` 确认改动范围，**不 `git add .` 盲提交**（本仓库已排除产物，风险较低）
4. 破坏性操作（`reset --hard`、`push --force`、删分支）**必须先问我**
5. 每次提交后报告：改了什么文件、commit hash、是否推送成功

## 五、提交信息怎么写

格式：`类型(范围): 中文说明`

| 类型 | 用在什么时候 |
| --- | --- |
| `feat` | 新功能（比如新增串口中断接收） |
| `fix` | 修 bug |
| `docs` | 只改了文档、日志、README |
| `chore` | 改配置、.gitignore、杂项 |
| `refactor` | 重构，不改功能 |

例子：
- `feat(uart): 增加串口中断接收与回显`
- `fix(clock): 修正 APB1 分频，串口波特率偏差`
- `docs(log): 补 2026-11-22 开发日志`

## 六、常用命令（手动看情况用）

```bash
git status                 # 当前改了哪些文件
git diff                   # 具体改了什么内容
git log --oneline -10      # 最近 10 次提交
git add <文件>             # 把文件放进"待提交"
git commit -m "说明"       # 拍快照
git push                   # 上传到 GitHub
git checkout -- <文件>      # 撤销某个文件的改动（危险：改动丢失）
git revert <hash>          # 撤销某次提交（安全，会生成新提交）
```

## 七、为什么要每天存档

- 飞控代码改到后面会越来越复杂，**能回退**是唯一的安全感
- GitHub 上的提交记录 = 你学习过程的履历，面试/保研/比赛都能拿出来给人看
- 日志里"今天学会了什么"积累三个月，比任何教程都贴合你自己的理解
