# 01 · 工程结构与启动流程

> 以 `1_代码/P01_flight_hal`（飞控）为主线，`P02_remote_hal`（遥控）结构相同。

## 一、目录分层

```
P01_flight_hal/
├── Core/                          # CubeMX 生成的初始化代码（尽量只改 USER CODE 区）
│   ├── Src/main.c                 # 入口：初始化 → 启动 RTOS
│   ├── Src/tim.c                  # TIM1~TIM4 四路 PWM 初始化
│   ├── Src/gpio.c                 # POWER_KEY 引脚初始化
│   ├── Src/usart.c                # USART2 调试串口
│   ├── Src/stm32f1xx_it.c         # 中断向量（SysTick 已接 FreeRTOS）
│   └── Inc/FreeRTOSConfig.h       # FreeRTOS 配置（主频/节拍/heap/优先级）
├── MDK-ARM/
│   ├── Application/               # 应用层：建任务、定周期、任务里干什么
│   │   └── APP_freertos_task.c/.h
│   ├── Interface/                 # 硬件接口层：一个硬件一个模块
│   │   ├── Int_Motor.c/.h         #   电机（PWM 占空比）
│   │   └── Int_IP5305T.c/.h       #   电源管理芯片（按键脉冲保活）
│   ├── Common/                    # 公共层
│   │   └── Com_debug.c/.h         #   printf 重定向 + Debug_Printf
│   └── P01_flight_hal.uvprojx     # Keil 工程
├── Drivers/                       # ST 官方 HAL + CMSIS（不改）
└── ../../FreeRtos/                # FreeRTOS 源码（Source / include / Protable）
```

**分层铁律**：上层可以调下层，下层**不能**调上层。`Interface` 里绝不能出现 `vTaskCreate` 之类的业务代码；`Application` 里绝不能直接操作寄存器。

## 二、上电到任务跑起来（完整调用链）

```
上电 / 复位
  │
  ├─ startup_stm32f103xb.s        Reset_Handler → SystemInit() → __main → main()
  │
  ├─ main()
  │   ├─ HAL_Init()               复位外设，初始化 SysTick（此时是 HAL 的 1ms 节拍）
  │   ├─ SystemClock_Config()     HSE 8MHz × PLL9 = 72MHz
  │   ├─ MX_GPIO_Init()           PA1/PA10/PB4/PB9 复用为 PWM，PB2 = POWER_KEY（初始高）
  │   ├─ MX_USART2_UART_Init()    115200 8N1
  │   ├─ MX_TIM1_Init()           TIM1_CH3  PWM
  │   ├─ MX_TIM2_Init()           TIM2_CH2  PWM
  │   ├─ MX_TIM3_Init()           TIM3_CH1  PWM
  │   ├─ MX_TIM4_Init()           TIM4_CH4  PWM
  │   └─ App_Freertos_Start()     ★ 从这里开始归 FreeRTOS 管
  │        ├─ xTaskCreate(Int_IP5305T_Task, 栈128, 优先级4)   ← 电源保活，最高优先级
  │        ├─ xTaskCreate(Int_Motor_Task,   栈128, 优先级3)   ← 电机控制
  │        └─ vTaskStartScheduler()                           ← 不返回
  │
  ├─ 调度器启动过程（FreeRTOS 内部）
  │   ├─ 创建空闲任务 Idle（优先级 0）
  │   ├─ 配置 SysTick 为 1ms（72000000/1000）
  │   └─ 触发 SVC 异常 → vPortSVCHandler → 启动第一个任务
  │
  └─ 之后全靠中断驱动：
      ├─ SysTick 每 1ms  → xPortSysTickHandler() → 判断是否该切换任务
      └─ PendSV          → xPortPendSVHandler()  → 真正做上下文切换
```

## 三、三个中断入口怎么交给 FreeRTOS（今天的重点）

Cortex-M3 有三个异常是 RTOS 的"基础设施"，必须由 FreeRTOS 接管，否则任务永远切不起来：

| 异常 | 谁在用 | 作用 |
| --- | --- | --- |
| `SVC_Handler` | HAL 默认是空的 | 调度器启动时启动第一个任务 |
| `PendSV_Handler` | HAL 默认是空的 | **真正的任务切换**（最低优先级，保证切换不打断别的中断） |
| `SysTick_Handler` | HAL 用来调 `HAL_IncTick()` | RTOS 的 1ms 节拍 |

本项目的解法（`FreeRTOSConfig.h`）：

```c
#define xPortPendSVHandler PendSV_Handler
#define vPortSVCHandler    SVC_Handler
```

这两行是**宏别名**：`port.c` 里的汇编函数 `xPortPendSVHandler` 在编译后直接叫 `PendSV_Handler`，于是向量表里的 `PendSV_Handler` 指到了 FreeRTOS 的实现。同时 `stm32f1xx_it.c` 里原来的 `PendSV_Handler` / `SVC_Handler` 空函数被**删掉**（否则重复定义）。

SysTick 不能这么简单粗暴地换，因为 HAL 还要靠 `HAL_IncTick()` 算超时（`HAL_Delay`、`HAL_UART_Transmit` 的超时都靠它）。所以改成"两个人合用"：

```c
void SysTick_Handler(void)
{
  if (xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED)
  {
    xPortSysTickHandler();   // 调度器启动后才喂 FreeRTOS
  }
  HAL_IncTick();             // HAL 的节拍照常走
}
```

> 为什么要判断状态？因为 `vTaskStartScheduler()` 之前 SysTick 就已经在跑了（`HAL_Init` 里配的），
> 那时 FreeRTOS 还没初始化，直接调 `xPortSysTickHandler` 会操作未初始化的就绪表 → 死机。
> 用 `xTaskGetSchedulerState()` 需要打开 `#define INCLUDE_xTaskGetSchedulerState 1`（已打开）。

## 四、两个任务

| 任务 | 优先级 | 栈 | 周期 | 职责 |
| --- | --- | --- | --- | --- |
| `Int_IP5305T_Task` | **4（最高）** | 128 字 | 10000 tick = **10s** | 拉低 POWER_KEY 100ms 再拉高，防止 IP5305T 自动断电 |
| `Int_Motor_Task` | 3 | 128 字 | 6 tick = **6ms** | 设置四路 PWM 占空比、启停电机（目前还是注释状态） |

两者都用 `vTaskDelayUntil`，保证严格周期、误差不累积。

## 五、四路 PWM 映射与频率

| 电机 | 引脚 | 定时器/通道 | Prescaler | ARR | 计数时钟 | PWM 频率 |
| --- | --- | --- | --- | --- | --- | --- |
| RIGHT_0 | PA1 | TIM2_CH2 | 4-1 | 1000-1 | 72M/4 = 18MHz | 18kHz |
| RIGHT_1 | PA10 | TIM1_CH3 | 4-1 | 1000-1 | 18MHz | 18kHz |
| LEFT_0 | PB4 | TIM3_CH1 | **0** ⚠️ | 1000-1 | 72M | **72kHz** ⚠️ |
| LEFT_1 | PB9 | TIM4_CH4 | 4-1 | 1000-1 | 18MHz | 18kHz |

计算方式：`PWM 频率 = 定时器时钟 ÷ (PSC+1) ÷ (ARR+1)`，`占空比 = CCR ÷ (ARR+1)`。

- 初始 `Pulse = 200` → 上电占空比 **20%**
- ⚠️ TIM3 少配了 Prescaler，四路频率不一致，**待修**（见第八节）

> **PB4 的隐患**：PB4 默认是 JTAG 的 `NJTRST`。本项目能用它做 PWM，是因为 CubeMX 里 `SYS → Debug` 选的是 **Serial Wire（只留 SWD）**，JTAG 被关掉后 PB4 才释放成普通引脚。如果哪天把 Debug 改回 JTAG，PB4 立刻失效。

## 六、数据流：从任务到引脚

```
Int_Motor_Task (6ms 一次)
   │  改 motor->speed
   ▼
Int_Motor_SetSpeed(&LEFT_0_motor)
   │  __HAL_TIM_SetCompare(htim, channel, speed)   ← 写 TIMx->CCR 寄存器
   ▼
定时器硬件比较 CCR 与 CNT
   │  CNT < CCR → 输出高电平；CNT ≥ CCR → 低电平
   ▼
PA1 / PA10 / PB4 / PB9 → 电调 → 电机
```

```
Int_IP5305T_Task (10s 一次)
   ▼
Int_IP5305T_Start()
   │  拉低 PB2 → vTaskDelay(100) → 拉高 PB2
   ▼
IP5305T 认为"按键还活着" → 继续保持输出 → 整机不断电
```

## 七、加一个新硬件模块的标准动作

以"加一个激光测高 VL53L4CD"为例：

1. `Interface/` 下新建 `Int_VL53L4CD.c/.h`，`.h` 里 `#include "main.h"`，先声明对外函数
2. `.h` 里写清头文件保护 `#ifndef __INT_VL53L4CD_H__` + `#define __INT_VL53L4CD_H__`（**两句必须一模一样**）
3. `.c` 里实现，只操作 HAL，不碰任务
4. `Application/APP_freertos_task.c` 里 `xTaskCreate` 建任务，周期用宏
5. CubeMX 里配好外设（I2C 等）→ 重新生成 → Keil 里把新 `.c` 加进工程
6. 编译 → 串口打印验证 → 提交
