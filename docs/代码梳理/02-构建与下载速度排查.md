# 02 · 编译与下载速度排查（为什么点一下要等 6 秒）

> 结论先行：**编译只要 1 秒，慢的是"每次都要把 uVision 整个加载一遍"，本机实测约 5 秒。**

## 一、现象

VS Code + Keil Assistant 里点"编译/下载"，感觉要等 6～10 秒；对比教程里的老师（同一套 Keil Assistant、同样没剪辑），他按一下就出结果。

## 二、实测数据（2026-11-25 本机）

| 操作 | 耗时 |
| --- | --- |
| Keil 日志里的 `Build Time Elapsed`（真正编译） | **1 秒** |
| 命令行 `UV4 -b` 增量编译（改 1 个文件，含进程启动） | 7.03 秒 |
| 命令行 `UV4 -b` 无改动 | 6.04 秒 |
| 命令行 `UV4 -r` 全量重编译（35 个 .c） | 26.18 秒 |
| **给一个不存在的工程，纯启动 UV4** | **5.07 秒** |
| 同机器启动 `armcc.exe`（对照） | 1.09 秒 |

**关键推论**：连"加载一个不存在的工程"都要 5 秒，说明这 5 秒和工程大小、代码量、器件包都无关，纯粹是 uVision 自身的启动开销。

## 三、逐项排除过的怀疑

| 怀疑 | 实验 | 结果 |
| --- | --- | --- |
| Keil 的 Browse Information 拖慢编译 | 关闭后全量重编译 | ✅ **确实是因素**：26.18s → 10.09s，已永久关闭（提交 `84ecf82`） |
| 器件包太大（PACK 876MB / 1025 个文件 / 1377 个 .pdsc） | 临时把整个 PACK 目录移走再启动 | ❌ 5.03s vs 5.07s，无影响 |
| 启动时联网校验数字签名 | 监听 UV4 进程启动期间的 TCP 连接 | ❌ 零网络连接（签名本身有效：ARM LTD） |
| 工程太大 / 文件太多 | 用不存在的工程启动 | ❌ 一样 5 秒 |
| 工程挂了编译前后脚本 | 检查 `RunUserProg1/2`、`CreateBatchFile` | ❌ 全是 0 |
| OneDrive 同步桌面 / 机械硬盘 | 检查 Desktop 路径、磁盘类型 | ❌ 桌面是本地路径、系统盘是 SSD |
| CPU 性能不足 | 查看硬件 | ❌ Ryzen 7 7435H，8 核 16 线程 |

**结论**：`C:\Keil_v5\UV4` 要加载 93 个文件（主程序 10MB + 一堆调试器 DLL：ULINK / J-Link / ST-Link / CMSIS-DAP），在这台机器上初始化要 5 秒。同盘 `armcc.exe` 启动也要 1.09 秒（正常应 0.1 秒级），说明机器上"启动程序"整体偏慢，UV4 加载得多就被放大。

**为什么老师快**：他那台机器 UV4 启动大概 1～2 秒（新装的 Keil、DLL 少、杀软放行），所以体验差 4～5 秒。不是操作问题，是环境差异。

## 四、三个解决方案（按成本排序，均未执行）

### ① 给 Windows Defender 加排除（免费，最可能有效）

管理员 PowerShell：

```powershell
Add-MpPreference -ExclusionPath 'C:\Keil_v5','C:\Users\24476\Desktop\四轴无人机项目'
Add-MpPreference -ExclusionProcess 'UV4.exe','armcc.exe','armlink.exe','fromelf.exe'
```

依据：`armcc.exe` 启动要 1.09 秒，很像实时扫描每个 DLL 造成的。加完用同样的方法复测启动时间即可验证。

### ② 重装一个"干净"的 Keil（约 1 小时）

只装 MDK Core + `Keil.STM32F1xx_DFP` + ST-Link 驱动，不装其他系列和多余调试器 DLL。
**不影响现有工程**：代码和 `.uvprojx` 都在项目目录里，重装后用 Keil 打开 `MDK-ARM/P01_flight_hal.uvprojx` 即可。

### ③ 换构建工具链（半天，一劳永逸）

CubeMX 可直接生成 **CMake 工程**，用 `ninja` + `arm-none-eabi-gcc`：

- 增量编译 < 1 秒，支持 8 核并行
- VS Code 里一个快捷键完成 build + flash，完全不启动 uVision
- 现有 FreeRTOS + 分层代码可原样搬过去，不用改写

## 五、当前采用的折中方案

**编译和下载都在 Keil 窗口里按 F7 / F8**（进程已经常驻，只花那 1 秒），VS Code 只用来写代码。零成本，能立刻得到接近教程的体验。

## 六、如果以后要复测

```powershell
# 测"纯启动"（给一个不存在的工程，立即退出）
Measure-Command { Start-Process 'C:\Keil_v5\UV4\UV4.exe' -ArgumentList @('-b','C:\nonexistent.uvprojx','-j0') -Wait -NoNewWindow }

# 测全量编译
Measure-Command { Start-Process 'C:\Keil_v5\UV4\UV4.exe' -ArgumentList @('-r','D:\path\to\xxx.uvprojx','-j0','-o',"$env:TEMP\b.log") -Wait -NoNewWindow }
```

对照基准：`纯启动 < 2 秒`、`全量编译 < 12 秒` 才算正常。
