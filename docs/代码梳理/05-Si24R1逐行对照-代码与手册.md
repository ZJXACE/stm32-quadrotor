## 2. `Int_SI24R1.h` 逐块讲解

### 2.1 第 1~4 行：头文件保护 + 引入 SPI

```c
1  #ifndef __nRF24L01P__
2  #define __nRF24L01P__
3
4  #include "spi.h"
```

| 行 | 在说什么 | 为什么必须这样 |
| --- | --- | --- |
| 1~2 | "如果没定义过 `__nRF24L01P__`，就定义它" | 防止同一个 `.h` 被两个 `.c` 包含时重复定义。**这两行的名字必须一字不差**（你这版是对的） |
| 3 | 空行 | 排版 |
| 4 | 引入 `spi.h` | 为了拿到 `hspi1` 这个 SPI 句柄的声明（CubeMX 生成在 `spi.c/.h` 里） |

**小改进（不影响功能）**：

- 宏名 `__nRF24L01P__` 是 nRF24 时代留下的，你的芯片是 Si24R1，建议改成 `__INT_SI24R1_H__`，以后看到名字就知道是哪个文件
- 更好的做法：`.h` 里只 `#include "main.h"`（它会链到 HAL），把 `spi.h` 放到 `.c` 里包含——这样头文件对外的依赖最小

### 2.2 第 8~9 行：两个宽度宏

```c
8  #define TX_ADR_WIDTH   5    // 5字节宽度的发送/接收地址
9  #define TX_PLOAD_WIDTH 32   // 数据通道有效数据宽度
```

| 宏 | 值 | 依据 | 说明 |
| --- | --- | --- | --- |
| `TX_ADR_WIDTH` | 5 | **P9 第 4.1 节**："地址长度可以通过配置寄存器 AW 配置为 3、或 4、或 5 字节" | 你选了 5 字节（`SETUP_AW` 默认 `11` 就是 5 字节，所以不用改） |
| `TX_PLOAD_WIDTH` | 32 | **P19 第 3.12 节**：`RX_PW_Px` "1~32 Bytes" | 你选了最大值 32。**收方 `RX_PW_P0` 必须也是 32**，否则长度对不上 |

**这两个值是"双方约定"**：地址宽度、负载长度，**收发两端必须一致**。它们错了，现象是"能发不能收"或"收到垃圾"。

> 想省空口时间可以改成 3 字节地址 + 8 字节负载，但**两端都要改**。

### 2.3 第 13~20 行：8 个 SPI 命令

```c
13  #define SI24R1_READ_REG    0x00   // 读寄存器（命令位）
14  #define SI24R1_WRITE_REG   0x20   // 写寄存器（命令位）
15  #define RD_RX_PLOAD        0x61   // 读 RX FIFO
16  #define WR_TX_PLOAD        0xA0   // 写 TX FIFO
17  #define FLUSH_TX           0xE1   // 清空 TX FIFO
18  #define FLUSH_RX           0xE2   // 清空 RX FIFO
19  #define REUSE_TX_PL        0xE3   // 重发上一包
20  #define NOP                0xFF   // 空操作（专门用来读 STATUS）
```

**逐个对照手册 P14 表 5-1**：

| 你的宏 | 值 | 手册命令名 | 手册写法 | 数据字节数 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `SI24R1_READ_REG` | 0x00 | `R_REGISTER` | `000A AAAA` | 1~5 | 命令位是 `000`，低 5 位放地址 |
| `SI24R1_WRITE_REG` | 0x20 | `W_REGISTER` | `001A AAAA` | 1~5 | 命令位是 `001`，低 5 位放地址 |
| `RD_RX_PLOAD` | 0x61 | `R_RX_PAYLOAD` | `0110 0001` | 1~32 | **读出后 FIFO 里这包就被删了** |
| `WR_TX_PLOAD` | 0xA0 | `W_TX_PAYLOAD` | `1010 0000` | 1~32 | ACK 模式发数据用这个 |
| `FLUSH_TX` | 0xE1 | `FLUSH_TX` | `1110 0001` | **0** | 清发送队列 |
| `FLUSH_RX` | 0xE2 | `FLUSH_RX` | `1110 0010` | **0** | 清接收队列；**回 ACK 完成前别清**，会当通信失败 |
| `REUSE_TX_PL` | 0xE3 | `REUSE_TX_PL` | `1110 0011` | **0** | 重发上一包；**FLUSH 或写新数据后不能用** |
| `NOP` | 0xFF | `NOP` | `1111 1111` | 0 | 只为了从 MISO 拿 STATUS |

**三条要记住的规则**：

1. **读命令不带 0x20，写命令带 0x20** —— 因为命令字高 3 位是"动作"，低 5 位是"地址"
2. **FLUSH 类命令数据字节数是 0** —— 你代码里 `SI24R1_Write_Reg(FLUSH_RX, 0xff)` 多发了一个字节（见 3.11 的问题）
3. `NOP` 不干什么，只用来"骗"出 STATUS —— 这是**最省事的读状态方式**

**手册里还有 4 个你没用到的命令**（第 5 节会讲什么时候用）：

| 命令 | 值 | 用途 |
| --- | --- | --- |
| `R_RX_PL_WID` | `0x60` | 动态长度时读"这包多少字节" |
| `W_ACK_PAYLOAD` | `0xA8｜pipe` | 回 ACK 时捎带数据（伪全双工） |
| `W_TX_PAYLOAD_NOACK` | `0xB0` | 发完就走，不等 ACK |
| `R_RX_PAYLOAD`/`W_TX_PAYLOAD` | 0x61/0xA0 | 你已经在用 |

这一整块**全部来自手册 P16~21 的"寄存器映射表"**，逐行对照如下：

| 你的行 | 宏 | 地址 | 手册页 | 手册原文摘要 |
| --- | --- | --- | --- | --- |
| 24 | `CONFIG` | 0x00 | P16 | 配置寄存器：中断屏蔽、CRC、上电、收发 |
| 25 | `EN_AA` | 0x01 | P16 | 使能自动确认（按管道） |
| 26 | `EN_RXADDR` | 0x02 | P17 | 使能接收数据管道地址 |
| 27 | `SETUP_AW` | 0x03 | P17 | 地址宽度 3/4/5 字节 |
| 28 | `SETUP_RETR` | 0x04 | P17 | 自动重发延时 ARD + 次数 ARC |
| 29 | `RF_CH` | 0x05 | P17 | 射频信道 0~125，间隔 1MHz |
| 30 | `RF_SETUP` | 0x06 | P18 | 速率 + 功率 + 测试模式 |
| 31 | `STATUS` | 0x07 | P18 | 状态/中断标志（MISO 第一字节就是它） |
| 32 | `OBSERVE_TX` | 0x08 | P18 | 丢包计数 + 重发计数 |
| 33 | `RSSI` | 0x09 | P19 | 1 位信号强度（>-60dBm） |
| 34 | `RX_ADDR_P0` | 0x0A | P19 | 管道 0 地址（5 字节全） |
| 35~39 | `RX_ADDR_P1~P5` | 0x0B~0x0F | P19 | P1 是 5 字节；**P2~P5 只有最低字节** |
| 40 | `TX_ADDR` | 0x10 | P19 | 发射地址（5 字节） |
| 41~46 | `RX_PW_P0~P5` | 0x11~0x16 | P19~20 | 各管道静态负载长度 1~32 |
| 47 | `FIFO_STATUS` | 0x17 | P21 | FIFO 满/空标志 |

**这块最容易忽略的两条**：

1. **`RX_ADDR_P2~P5` 只有 1 个字节**（P19 原文："接收地址高字节与 RX_ADDR_P1[39:8] 相同"）。所以想做"6 个完全不同地址"是**做不到**的——这是硬件限制，不是代码问题。
2. **`RX_PW_Px` 默认值是 0**（P19 Reset Value 列），也就是**默认关着**。你代码里写了 32，是对的；如果忘了写，就是"能收但不给数据"。

**你的头文件还缺 3 个寄存器**（第 5 节讲用途时要用）：

| 缺的 | 地址 | 什么时候需要 |
| --- | --- | --- |
| `DYNPD` | 0x1C | 想用动态负载长度 |
| `FEATURE` | 0x1D | 想用 ACK 载荷 / NO_ACK / 动态长度 |
| `RSSI` 你有了，但 `OBSERVE_TX` 没用在代码里 | 0x08 | 想看链路质量 |

### 2.5 第 51~53 行：STATUS 的三个位（★全文件最容易错的地方）

```c
51  #define RX_DR   0x40
52  #define TX_DS   0x20
53  #define MAX_RT  0x10
```

**你的值是对的**。依据手册 **P18 STATUS 寄存器**：

| 位 | Si24R1 名字 | 掩码 | 手册原文 |
| --- | --- | --- | --- |
| 7 | Reserved | — | 保留，0 |
| **6** | `RX_DR` | **0x40** | RX FIFO 有值标志位，写 1 清除 |
| **5** | `TX_DS` | **0x20** | 发射完成中断位，收到 ACK 后置 1，写 1 清除 |
| **4** | `MAX_RT` | **0x10** | 达到最大重发次数中断位，写 1 清除 |
| 3:1 | `RX_P_NO` | 0x0E | 收到数据的管道号；**111 = FIFO 空** |
| 0 | `TX_FULL` | 0x01 | TX FIFO 满 |

**⚠️ 为什么这里必须查手册**：nRF24L01+ 的 STATUS 是 bit7=RX_DR（0x80）、bit6=TX_DS（0x40）、bit5=MAX_RT（0x20）。**Si24R1 把 bit7 留空了，整体右移一位**。

网上 90% 的 Si24R1 代码是从 nRF24 抄的，掩码没改。后果：

- 用 `0x80` 判断"收到数据" → 永远不成立 → 收不到
- 用 `0x40` 判断"发送成功" → 实际测的是 RX_DR → 发送永远"失败"

**编译不报错、逻辑看着对、就是不通**——这种坑只能靠对表发现。

**也别忘了掩码表里还有两位**（你头文件没写，但调试时有用）：

```c
#define TX_FULL  0x01     /* bit0：TX FIFO 满 */
#define RX_P_NO  0x0E     /* bit3:1：管道号 */
```

## 3. `Int_SI24R1.c` 逐行讲解

### 3.1 第 1~3 行：引入 + 全局地址

```c
1  #include "Int_SI24R1.h"
2  //SI24R1发送地址和接受地址是同一个地址
3  uint8_t TX_ADDRESS[TX_ADR_WIDTH] = {0x0A,0x01,0x06,0x0E,0x01};
```

| 行 | 在说什么 | 依据 |
| --- | --- | --- |
| 1 | 引入自己的头文件 | — |
| 3 | 定义 5 字节"门牌号"，收发共用 | **P9 第 4.1 节**：地址字段；**P19 `TX_ADDR` 说明**：若要收 ACK，`RX_ADDR_P0` 要等于 `TX_ADDR` |

**手册里两条硬规矩，你的地址刚好都满足**：

1. **P9 第 4.1 节**：地址最高字节不可为 `0xFF、0x00、0xA5、0x5A、0xAA、0x55`
   - 你的数组 `[0]=0x0A` 是最低字节（**LSByte 先写**，P19 原文），所以最高字节是 `[4]=0x01` → **安全** ✅
2. **P19**：`RX_ADDR_P0` 默认值是 `0xE7E7E7E7E7`，如果不写，你就在听一个"全员默认地址"，容易和别人串台

**改进建议**：把最后一个字节做成"机号"，多机时只改一个数：

```c
uint8_t TX_ADDRESS[5] = {0x0A, 0x01, 0x06, 0x0E, DEVICE_ID};   /* DEVICE_ID 从宏来 */
```

### 3.2 第 6~9 行：`SPI_RW` —— 全文件唯一碰硬件的地方

```c
6  static uint8_t SPI_RW(uint8_t byte)
7  {
8      HAL_SPI_TransmitReceive(&hspi1,&byte,)
9  }
```

| 行 | 在说什么 | 依据 |
| --- | --- | --- |
| 6 | 收 1 字节、发 1 字节、返回收到的字节 | **P14 第 5.1 节**："每一次 SPI 操作，MISO 输出的第一字节为状态寄存器的值" |
| 8 | **⚠️ 这行没写完**，缺接收缓冲、长度、超时 | 参数格式来自 HAL，不是手册 |

**正确写法**：

```c
static uint8_t SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;
}
```

**每个参数为什么这么填**：

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| `&hspi1` | CubeMX 生成的句柄 | 定义在 `spi.c` |
| `&byte` | 要发的 1 字节 | 发送缓冲地址 |
| `&rx` | 接收缓冲 | **必须给**，否则收到的字节没地方放 |
| `1` | 长度 1 字节 | 一次换 1 个字节 |
| `100` | 超时 100ms | 防止总线异常时死等 |

**为什么用 `TransmitReceive` 而不是 `Transmit`**：SPI 是"发一个同时收一个"，只用 `Transmit` 收到的字节会被丢掉——你就读不到寄存器值了（`Read_Reg` 会全返回 0）。

**和手册对得上的三个点**：

1. **P14**：CSN 从高翻低，SPI 开始工作 → 所以这个函数外面必须由 `CSN=0/1` 包住
2. **P15 表 5-1**：`Fsck` 最高 **10MHz** → HAL 分频后 9MHz（72M/8）合规
3. **P15**：`Tcd`（SCK 到数据有效）58ns → 硬件 SPI 由外设保证，软件 SPI 要注意加延时

### 3.3 第 17~23 行：`SI24R1_Init` —— 上电静默

```c
17  void SI24R1_Init(void)
18  {
19      SCK = 0;      //SPI时钟线拉低
20      CSN = 1;
21      CE  = 0;
22      IRQ = 1;
23  }
```

| 行 | 动作 | 为什么 | 依据 |
| --- | --- | --- | --- |
| 19 | SCK 拉低 | SPI 空闲电平必须是低（模式 0） | P15 图 5-3 时序（SCK 空闲低） |
| 20 | CSN 拉高 | 不选中，防止上电抖动被误当命令 | P14："CSN 从高翻低，SPI 开始工作" |
| 21 | CE 拉低 | 关掉收发，配置期间不工作 | P7 第 3.1.2："CE=0 时从 TX/RX 返回 Standby" |
| 22 | **IRQ = 1** | ⚠️ **这行有问题**：IRQ 是**输入脚**（P5 引脚表：IRQ = DO），给输入脚写电平无意义 | P5 |

**`IRQ = 1` 应该怎么处理**：

- 如果 CubeMX 里把 IRQ 配成**上拉输入**（推荐），这行直接删掉
- 如果是外部中断，配置成 `GPIO_MODE_IT_FALLING`（低电平有效，P5 原文"低电平有效"）
- **绝对不要**把 IRQ 配成输出

**还缺一步：上电延时**

**P6 图 3-1 注释**："VDD>=1.9V 上电延时 100ms"。所以更完整的写法：

```c
void Int_SI24R1_Init(void)
{
    HAL_Delay(100);                       /* P6：上电延时 100ms */
    HAL_GPIO_WritePin(CSN_PORT, CSN_PIN, GPIO_PIN_SET);
    HAL_GPIO_WritePin(CE_PORT,  CE_PIN,  GPIO_PIN_RESET);
}
```

> 硬件 SPI 下 `SCK = 0` 这行可以删——SCK 由 SPI 外设管，你手动写它反而可能干扰外设状态。

### 3.4 第 32~42 行：`SI24R1_Write_Reg` —— 写一个寄存器

```c
32  uint8_t SI24R1_Write_Reg(uint8_t reg, uint8_t value)
33  {
34      uint8_t status;
36      CSN = 0;
37      status = SPI_RW(reg);
38      SPI_RW(value);
39      CSN = 1;
41      return(status);
42  }
```

**逐行对照手册**：

| 行 | 动作 | 依据 |
| --- | --- | --- |
| 36 | 拉低 CSN，开始一帧 | **P14**："CSN 从高电平翻转为低电平，SPI 接口开始工作" |
| 37 | 发命令字节，**同时接住 STATUS** | **P14**："MISO 输出的第一字节为状态寄存器的值" |
| 38 | 发数据字节 | **P14 表 5-1**：`W_REGISTER` 后跟 1~5 个数据字节 |
| 39 | 拉高 CSN，芯片执行写入 | **P15 图 5-1**：一帧以 CSN 上升沿结束 |
| 41 | 返回 STATUS | 手册允许，顺带拿到，不额外花时间 |

**为什么第 37 行要 `status =`**：因为 SPI 全双工，发命令的 8 个时钟里芯片**同时**在 MISO 上吐 STATUS。不接就浪费了。

**`reg` 怎么传**：调用者要自己拼命令位：

```c
SI24R1_Write_Reg(SI24R1_WRITE_REG + RF_CH, 40);   /* ✅ 0x20 + 0x05 */
SI24R1_Write_Reg(RF_CH, 40);                      /* ❌ 0x05 是"读"，芯片不会写 */
```

**一个手册提醒（P14 表 5-1 备注）**：

> `W_REGISTER` "只允许 Shutdown、Standby、Idle-TX 模式下操作"。

所以：**CE=1 正在接收时调这个函数，可能写不进去**。实践上要养成"改配置前先 CE=0"的习惯。

### 3.5 第 52~63 行：`SI24R1_Write_Buf` —— 连续写

```c
52  uint8_t SI24R1_Write_Buf(uint8_t reg, const uint8_t *pBuf, uint8_t bytes)
53  {
54      uint8_t status,byte_ctr;
56      CSN = 0;
57      status = SPI_RW(reg);
58      for(byte_ctr=0; byte_ctr<bytes; byte_ctr++)
59          SPI_RW(*pBuf++);
60      CSN = 1;
62      return(status);
63  }
```

| 行 | 动作 | 说明 |
| --- | --- | --- |
| 52 | `const uint8_t *pBuf` | `const` = 只读，函数不会改你的数据（好习惯） |
| 57 | 只发**一次**命令 | **P14**：`W_REGISTER` 支持 1~5 个数据字节，芯片自动往 `addr+1` 递增 |
| 58~59 | 循环发 N 个 | `*pBuf++` = 先取当前字节，再把指针挪到下一个 |
| 60 | 最后才拉高 CSN | **关键**：中途拉高会被当成"一帧结束"，地址就写断了 |

**为什么地址必须用它**：

`RX_ADDR_P0`、`TX_ADDR` 是 **5 个连续地址的寄存器**（0x0A~0x0E）。**P19**："最大宽度为 5bytes (LSByte 最先写入)"。

如果你用 `Write_Reg` 写 5 次：

```
第1次：CSN低 命令 数据  CSN高   ← 芯片认为写完一帧
第2次：CSN低 命令 数据  CSN高   ← 又一次独立写入
...
```

每次都会被当成"写同一个寄存器"，结果**只有最后一个字节生效**，地址永远是错的。

### 3.6 第 71~81 行：`SI24R1_Read_Reg` —— 读一个寄存器

```c
71  uint8_t SI24R1_Read_Reg(uint8_t reg)
72  {
73      uint8_t value;
75      CSN = 0;
76      SPI_RW(reg);
77      value = SPI_RW(0);
78      CSN = 1;
80      return(value);
81  }
```

| 行 | 动作 | 依据 |
| --- | --- | --- |
| 76 | 发读命令（**不带 0x20**） | **P14 表 5-1**：`R_REGISTER` = `000A AAAA` |
| 77 | **发空转字节**，把这 8 个时钟里收到的值存下来 | **P14**：命令之后"通过命令来确定是否输出值"——读命令会继续输出寄存器值 |
| 78 | 拉高 CSN | 结束帧 |

**为什么必须多发一个字节**：命令字节的 8 个时钟，芯片在**接收命令**，它把寄存器值准备好了但还没开始吐；要有**第二组 8 个时钟**，它才会把值移出来。空转字节发 `0x00` 还是 `0xFF` 都行——**内容无所谓，只要给满 8 个时钟**。

**返回值**：`value` 就是寄存器值。注意它**不是** STATUS（STATUS 在第 76 行被丢掉了）。想同时拿 STATUS 就写 `status = SPI_RW(reg);`。

### 3.7 第 91~102 行：`SI24R1_Read_Buf` —— 连续读

```c
91  uint8_t SI24R1_Read_Buf(uint8_t reg, uint8_t *pBuf, uint8_t bytes)
92  {
93      uint8_t status,byte_ctr;
95      CSN = 0;
96      status = SPI_RW(reg);
97      for(byte_ctr=0;byte_ctr<bytes;byte_ctr++)
98          pBuf[byte_ctr] = SPI_RW(0);
99      CSN = 1;
101     return(status);
102 }
```

| 行 | 动作 | 依据 |
| --- | --- | --- |
| 96 | 发读命令，接住 STATUS | P14 |
| 97~98 | 每个字节发一次空转、收一个值 | P14：读命令可以连续读 1~32 字节（FIFO） |
| 99 | 拉高 CSN | 结束 |

**用途**：主要用来读 **RX FIFO**（`RD_RX_PLOAD`，一次读 32 字节），这也是 `RxPacket` 里唯一的读数据手段。

**一个容易忽略的点**：读 FIFO 后，**这包数据就从 FIFO 里删掉了**（P14 表 5-1 原文："读出后 FIFO 数据被删除"）。所以读之前一定要确认 `RX_DR`，别乱读。

### 3.8 第 110~122 行：`SI24R1_RX_Mode` —— 配成接收模式（9 步）

```c
110  void SI24R1_RX_Mode(void)
111  {
112      CE = 0;
113      SI24R1_Write_Buf(WRITE_REG + RX_ADDR_P0, TX_ADDRESS, TX_ADR_WIDTH);
114      SI24R1_Write_Reg(WRITE_REG + EN_AA, 0x01);
115      SI24R1_Write_Reg(WRITE_REG + EN_RXADDR, 0x01);
116      SI24R1_Write_Reg(WRITE_REG + RF_CH, 40);
117      SI24R1_Write_Reg(WRITE_REG + RX_PW_P0, TX_PLOAD_WIDTH);
118      SI24R1_Write_Reg(WRITE_REG + RF_SETUP, 0x0f);
119      SI24R1_Write_Reg(WRITE_REG + CONFIG, 0x0f);
120      SI24R1_Write_Reg(WRITE_REG + STATUS, 0xff);
121      CE = 1;
122  }
```

**逐行对照（每行都能在手册里找到依据）**：

| 行 | 写哪个寄存器 | 值 | 手册页 | 这个值在说什么 |
| --- | --- | --- | --- | --- |
| 112 | — | `CE=0` | **P7 3.1.2** | 回到 Standby，**只有这样才能改寄存器**（P14 表 5-1 备注） |
| 113 | `RX_ADDR_P0` | 5 字节地址 | **P19** | 管道 0 完整地址；LSByte 先写 |
| 114 | `EN_AA` | `0x01` | **P16~17** | `ENAA_P0=1`：管道 0 收到包**自动回 ACK** |
| 115 | `EN_RXADDR` | `0x01` | **P17** | `ERX_P0=1`：**打开管道 0 的接收开关** |
| 116 | `RF_CH` | `40` | **P17** | 频率 = 2400 + 40 = **2440MHz** |
| 117 | `RX_PW_P0` | `32` | **P19~20** | 管道 0 每包**固定收 32 字节**（1~32） |
| 118 | `RF_SETUP` | `0x0F` | **P18** | 见下方位解码 |
| 119 | `CONFIG` | `0x0F` | **P16** | 见下方位解码 |
| 120 | `STATUS` | `0xFF` | **P18** | 写 1 清零：把 RX_DR/TX_DS/MAX_RT 全清 |
| 121 | — | `CE=1` | **P7 3.1.5** | 进入 RX，**120~130us 后**真正开始监听 |

**第 118 行 `0x0F` 位解码（P18 RF_SETUP）**：

```
0x0F = 0000 1111
       ││││ └┴┴─ RF_PWR[2:0] = 111 → +7dBm（最大功率）
       │││└───── RF_DR_HIGH = 1  ┐
       ││└────── PLL_LOCK = 0    ├ 组合 [LOW,HIGH]=01 → 2Mbps
       │└─────── RF_DR_LOW = 0   ┘
       └──────── CONT_WAVE = 0（平时必须 0，产测才置 1）
```

**第 119 行 `0x0F` 位解码（P16 CONFIG）**：

```
0x0F = 0000 1111
       ││││ └┴┴─ 保留位（bit7~4）
       ││││         bit6 MASK_RX_DR  = 0 → 收到数据会拉低 IRQ
       ││││         bit5 MASK_TX_DS  = 0 → 发送完成会拉低 IRQ
       ││││         bit4 MASK_MAX_RT = 0 → 重发超限会拉低 IRQ
       │││└──── bit3 EN_CRC  = 1 → 开 CRC
       ││└───── bit2 CRCO    = 1 → CRC 16 位
       │└────── bit1 PWR_UP  = 1 → 上电
       └─────── bit0 PRIM_RX = 1 → 接收模式 ★
```

**这 9 步的顺序为什么不能乱**：

- **112 必须最先**（P14：写寄存器只在 Shutdown/Standby/Idle-TX 允许）
- **121 必须最后**（`CE=1` 之后芯片就开始工作，此时再改寄存器可能被忽略）
- **120 在 119 之后**：先进入接收模式再清标志，避免"刚清完又进一个旧包"

**你这段代码的一个小隐患**：第 120 行 `STATUS = 0xFF` 会**清掉所有标志**，包括可能刚收到的包对应的 `RX_DR`——如果上电瞬间正好有包进来，会被当成"没收到"。影响很小，但严格的做法是**只清你想清的那几位**。

### 3.9 第 130~143 行：`SI24R1_TX_Mode` —— 配成发送模式

```c

```

**和 `RX_Mode` 的 5 处差异（记住这 5 条就够）**：

| 行 | 差异 | 为什么 | 手册依据 |
| --- | --- | --- | --- |
| 133 | **多写 `TX_ADDR`** | 发送端要知道"喊谁" | P19：发射方地址 |
| 134 | 仍写 `RX_ADDR_P0` | **为了收 ACK**：对方回的 ACK 发到这个地址 | P10 第 4.2.1："发送端需要设置接收管道 0 地址与自身发送地址相同" |
| 138 | **多配 `SETUP_RETR=0x0A`** | 只有发送需要重发策略 | P17：ARD=0000→250us；ARC=1010→重发 10 次 |
| 141 | `CONFIG=0x0E`（bit0=0） | 唯一的模式开关：`PRIM_RX=0` → 发送 | P16 CONFIG bit0 |
| 142 | `CE=1` 被注释掉 | 发射靠 `TxPacket` 里的 CE 脉冲触发，不在这里常开 | P7 3.1.4：CE 高脉冲 ≥10us |

**第 138 行 `0x0A` 位解码（P17 SETUP_RETR）**：

```
0x0A = 0000 1010
       └┬─┘ └┬─┘
     ARD=0000  ARC=1010
     250us     10 次
```

最坏情况耗时 ≈ 10 × (250us + 86us) ≈ **3.4ms**。如果对实时性敏感，把 ARC 降到 2~3。

**第 133/134 行为什么要写两遍 `TX_ADDRESS`**：一次写到 `TX_ADDR`（我喊谁），一次写到 `RX_ADDR_P0`（我听谁的 ACK）。**两处必须是同一个地址**，否则"发出去了但永远收不到 ACK"。

### 3.10 第 152~165 行：`SI24R1_RxPacket` —— 取一包

```c
152  uint8_t SI24R1_RxPacket(uint8_t *rxbuf)
153  {
154      uint8_t state;
155      state = SI24R1_Read_Reg(STATUS);
156      SI24R1_Write_Reg(WRITE_REG+STATUS,state);
158      if(state & RX_DR)
159      {
160          SI24R1_Read_Buf(RD_RX_PLOAD,rxbuf,TX_PLOAD_WIDTH);
161          SI24R1_Write_Reg(FLUSH_RX,0xff);
162          return 0;
163      }
164      return 1;
165  }
```

| 行 | 动作 | 依据 | 说明 |
| --- | --- | --- | --- |
| 155 | 读 STATUS | **P18** | 看芯片有没有收到东西 |
| 156 | 把读到的值**写回** STATUS | **P18**："写 1 清除" | 读到的 1 原样写回去 = 把置位的位清掉。这是"写 1 清零"的经典用法 |
| 158 | 判断 `RX_DR`（0x40） | **P18 bit6** | 为 1 = FIFO 里有数据 |
| 160 | `R_RX_PAYLOAD` 读 32 字节 | **P14 表 5-1** | 读出后这包**自动从 FIFO 删除** |
| 161 | 清 RX FIFO | **P14** | 防止残留（见下方问题） |
| 162 | 返回 0 | — | **0 = 成功，1 = 没数据**（和很多库相反，注意别写反） |

**两个问题**：

**① 第 156 行"整字节写回"的副作用**

`state` 里包含只读的 `RX_P_NO`（bit3:1）。写回去时这几位会被忽略（P18 标了 `R`），所以**不会出错**，但更干净的做法是只清你要清的位：

```c
SI24R1_Write_Reg(SI24R1_WRITE_REG + STATUS, RX_DR);   /* 只清"收到数据" */
```

**② 第 161 行 `FLUSH_RX` 多发了一个字节**

`FLUSH_RX` 是**0 数据字节**的命令（P14 表 5-1）。你用的是 `Write_Reg(FLUSH_RX, 0xff)`，实际发出了"命令 + 1 个字节"，多出的那个字节在时序上属于"额外时钟"。

多数情况下芯片能容忍（不会出错），但严格按手册应该是：

```c
CSN = 0;  SPI_RW(FLUSH_RX);  CSN = 1;      /* 纯命令，不带数据 */
```

建议加一个 `SI24R1_Cmd()` 专门发纯命令（见第 5.3 节）。

**还有一个隐患**：第 156 行在 **RX 模式（CE=1）** 下写寄存器。P14 表 5-1 写着 `W_REGISTER` 只允许在 Shutdown/Standby/Idle-TX 操作。实测常有概率成功，但**严谨做法**是：

```c
CE = 0;                                   /* 回 Standby */
SI24R1_Write_Reg(WRITE_REG + STATUS, RX_DR);
CE = 1;                                   /* 重新进 RX */
```

### 3.11 第 175~195 行：`SI24R1_TxPacket` —— 发一包

```c
175  uint8_t SI24R1_TxPacket(uint8_t *txbuf)
176  {
177      uint8_t state;
178      CE=0;
179      SI24R1_Write_Buf(WR_TX_PLOAD, txbuf, TX_PLOAD_WIDTH);

193      }
194      return 0XFF;

```

**逐行对照（这是全文件最需要理解时序的一段）**：

| 行 | 动作 | 依据 | 为什么必须这样 |
| --- | --- | --- | --- |
| 178 | `CE=0` | **P7 3.1.2** | CE=1 时在收/发，**不能写 FIFO**；必须先回 Standby |
| 179 | `W_TX_PAYLOAD` 写 32 字节 | **P14** | 写进 TX FIFO |
| 180 | `CE=1` | **P7 3.1.4** | TX FIFO 有数据 + CE=1 → 进入 TX，**CE 高至少 10us** |
| 182 | 等 IRQ 变低 | **P1 引脚表**："IRQ 低电平有效" | 发完（成功或失败）IRQ 会拉低 |
| 183 | 读 STATUS | **P18** | 看是 `TX_DS` 还是 `MAX_RT` |
| 184 | 清标志 | **P18**："写 1 清除" | **不清就不能发下一包**（P10："MAX_RT 中断在清除之前不能进行下一步的数据发送"） |
| 185~189 | `MAX_RT` → 清 TX FIFO，返回 0x10 | **P18 bit4**、**P14 `FLUSH_TX`** | 失败要清队列，否则残留包会阻塞 |
| 190~193 | `TX_DS` → 返回 0x20 | **P18 bit5** | 成功 |
| 194 | 返回 0xFF | — | 兜底：既没成功也没失败（极少见） |

**返回值检查**：`MAX_RT` 宏在头文件里是 `0x10`，`TX_DS` 是 `0x20`，和手册 P18 完全一致 ✅

**这一段最大的问题：第 182 行 `while(IRQ == 1);` 没有超时。**

如果出现以下任一情况，程序会**永久卡死**在这行：

- 对方没开机
- 地址/频道配错
- 天线没接（发射失败，但 IRQ 可能不按预期翻转）
- CE 电平没真正拉高（GPIO 配错）

**改成带超时的版本**：

```c
uint32_t timeout = 50000;                  /* 约 50ms，按主频调整 */
while (IRQ == 1) {
    if (--timeout == 0) {
        SI24R1_Write_Reg(FLUSH_TX, 0xFF);  /* 清队列，避免残留 */
        return 0xFF;                        /* 超时 = 失败 */
    }
}
```

**还有一个小问题**：第 187 行 `FLUSH_TX` 同样是"0 数据字节"命令，和第 161 行一样多发了字节。

**第 180 行 `CE=1` 之后为什么不拉低**：代码靠"下次进 `TxPacket` 时第 178 行拉低"来复位。能跑，但**更稳的写法**是在函数末尾 `CE=0`，让芯片明确回到 Standby。

### 任务 2：去掉死等（10 分钟）

`TxPacket` 第 182 行加超时计数（代码见 3.11）。**这是"能跑"和"跑着不死机"的分界线。**

### 任务 3：加纯命令函数（5 分钟）

```c
static void SI24R1_Cmd(uint8_t cmd)
{
    CSN = 0;
    SPI_RW(cmd);
    CSN = 1;
}
```

把两处 `Write_Reg(FLUSH_xx, 0xff)` 换成 `SI24R1_Cmd(FLUSH_xx)`。

### 任务 4：改配置前必须 CE=0（5 分钟）

在 `RxPacket` 清标志前加 `CE=0` / `CE=1`（见 3.10 末尾）。

### 任务 5：把链路质量打出来（20 分钟）

```c
uint8_t obs = SI24R1_Read_Reg(OBSERVE_TX);      /* P18 */
Debug_Printf("丢包=%d 重发=%d\r\n", (obs>>4)&0x0F, obs&0x0F);
```

**这一步做完，你就有了"判断链路好不好"的数据依据**，而不是靠猜。

### 任务 6：接上你的 LED 状态机（30 分钟）

```c
/* 在 Int_Led_Task 里 */
if (retry > 3)      plane_state = Error;    /* 链路差 → 故障灯 */
else if (retry > 0) plane_state = IDLE;     /* 勉强通 → 慢闪 */
else                plane_state = FLIGHT;   /* 通畅 → 快闪 */
```

**这就是"把驱动变成产品"的第一步**：数据 → 状态 → 人能看懂的指示。

## 6. 想做成"产品级"，还差 5 件

| # | 缺口 | 怎么补 | 收益 |
| --- | --- | --- | --- |
| 1 | 函数返回值语义混乱（0/1/0x10/0x20/0xFF） | 定义枚举：`SI24R1_OK / TIMEOUT / NO_ACK / BAD_LEN` | 上层好判断 |
| 2 | 没有长度校验 | 读包后判断 `len <= 32`，否则 FLUSH | 防越界 |
| 3 | 没有重试策略 | 失败重发 2 次，再失败上报 | 提高成功率 |
| 4 | 没有状态机 | 把"配置/发送/接收/休眠"做成状态，避免乱序调用 | 防误用 |
| 5 | 直接暴露寄存器操作 | Application 只调 `SI24R1_Send()/Recv()` | 换芯片只改 Interface 层 |

**配套的接口设计（推荐）**：

```c
typedef enum {
    SI24R1_OK = 0,
    SI24R1_NO_DATA,
    SI24R1_TIMEOUT,
    SI24R1_NO_ACK,
    SI24R1_ERR_LEN,
} SI24R1_Status;

SI24R1_Status SI24R1_Send(const uint8_t *buf, uint8_t len);
SI24R1_Status SI24R1_Recv(uint8_t *buf, uint8_t *len);
SI24R1_Status SI24R1_Check(uint8_t *retry, uint8_t *lost);   /* 读 OBSERVE_TX */
```

## 7. 自检剧本：4 步，每步都有"预期输出"

**照顺序做，任一步失败就停下修，别跳。**

### 第 1 步：能不能读到寄存器

```c
uint8_t cfg = SI24R1_Read_Reg(CONFIG);
Debug_Printf("CONFIG = 0x%02X\r\n", cfg);
```

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `0x08` 左右（默认值） | SPI 通了 ✅ | 进第 2 步 |
| `0x00` 或 `0xFF` | SPI 没通 | 查 CSN 是否真拉低、MISO 接线、SPI 模式 |
| 其他乱值 | 时序有问题 | 降 SPI 频率到 1MHz 再试 |

### 第 2 步：能不能写进去

```c
SI24R1_Write_Reg(SI24R1_WRITE_REG + RF_CH, 40);
if (SI24R1_Read_Reg(RF_CH) == 40) Debug_Printf("写读 OK\r\n");
```

| 结果 | 含义 |
| --- | --- |
| 读回 40 | 命令拼对了 ✅ |
| 读回别的 | 命令位错（忘了 `+0x20`，或用了 `WRITE_REG` 未定义变量） |

### 第 3 步：进接收模式看状态

```c
SI24R1_RX_Mode();
Debug_Printf("STATUS=0x%02X\r\n", SI24R1_Read_Reg(STATUS));
```

预期：`STATUS` 的 `RX_P_NO`（0x0E）应该是 **0x0E**（=111，FIFO 空），其他位 0。

### 第 4 步：两块板对发

| 现象 | 说明 |
| --- | --- |
| A 返回 0x20，B 收到 | 全通 🎉 |
| A 返回 0x10 | B 没回 ACK：地址/频道/速率不一致，或 B 没进 RX |
| 两块都 0xFF | `SPI_RW` 还没修好，或 IRQ 没接对 |
