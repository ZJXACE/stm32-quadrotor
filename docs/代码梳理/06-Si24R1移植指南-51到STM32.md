# 06 · 移植指南：51 / 通用驱动 → STM32 HAL（按你的引脚）

> 对象：`Int_SI24R1.c/.h`（目前还是 51/正点原子风格的直写端口写法）
> 目标：改成能在你这块板子上编译、跑的 STM32 HAL 版本
> 依据：`Si24R1_数据手册_V1.3.pdf` + 你工程的 `P01_flight_hal.ioc`

---

## 0. 先说结论：要改的只有 4 类东西

| 类别 | 原代码长什么样 | 为什么必须改 | 改完长什么样 |
| --- | --- | --- | --- |
| **① 引脚操作** | `SCK = 0;` `CSN = 1;` `CE = 0;` `IRQ = 1;` | 这些是 51 的 `sbit` 或正点原子的位带宏，STM32 HAL 工程里**根本不存在** | `HAL_GPIO_WritePin(端口, 引脚, 电平)` 或硬件 SPI 自动 |
| **② 数据类型** | `u8` / `u16` | 51 的 typedef，STM32 工程没定义 | `uint8_t` / `uint16_t` |
| **③ 延时** | `delay_us(10)` | 51 的软延时函数，没有 | `HAL_Delay()` 或 DWT 微秒延时 |
| **④ SPI 收发** | 软件翻转 SCK/MOSI/MISO | 51 没有硬件 SPI；STM32 有，用起来快 10 倍 | `HAL_SPI_TransmitReceive()` |

**不用改的**：所有寄存器地址宏、命令宏、STATUS 位宏、时序逻辑——**这些是芯片手册决定的，跟 MCU 无关**。

## 1. 你的板子到底怎么接的（从 CubeMX 里读出来的真实结果）

### 1.1 已确认的引脚

| 信号 | STM32 引脚 | CubeMX 里的名字 | 配置 | 你能不能直接用 |
| --- | --- | --- | --- | --- |
| SCK | **PA5** | `SPI1_SCK` | 复用推挽（AF_PP） | ✅ 硬件 SPI 自动驱动 |
| MISO | **PA6** | `SPI1_MISO` | 输入 | ✅ |
| MOSI | **PA7** | `SPI1_MOSI` | 复用推挽（AF_PP） | ✅ |
| **CSN** | **PA4** | `SPI1_NSS` | GPIO 输出，初始**高** | ✅ 宏 `SPI1_NSS_Pin` |
| **CE** | **PA8**（待你确认） | `SP_EN` | GPIO 输出，初始**低** | ⚠️ 见 1.2 |
| **IRQ** | **没有** | — | — | ❌ **必须处理**，见 1.3 |

### 1.2 `SP_EN`（PA8）是不是 Si24R1 的 CE？

从工程看：`PA8` 是普通 GPIO 输出、初始低电平，名字 `SP_EN`（我推测是 "Si24R1 Power ENable"）。

**验证方法（30 秒）**：

1. 把 `PA8` 用 `HAL_GPIO_WritePin` 拉到高
2. 然后进 `RX_Mode`，看能不能收到数据
3. 如果拉高后能收、拉低后收不到 → 它就是 CE，确认了

**如果不是 CE**（比如是功放供电、蜂鸣器使能），那你就**还有一根 CE 线没接到 STM32**，必须找出来——CE 是收发总开关，没它芯片永远待机（手册 **P7 3.1.2**：`CE=1` 才进 RX/TX）。

### 1.3 IRQ 没配 —— 这是必须解决的坑

原驱动里有两处依赖 IRQ：

```c
while(IRQ == 1);              /* TxPacket 第 182 行：等发送完成 */
```

手册 **P1 引脚表**写着：`IRQ` 是芯片的**输出**，低电平有效。如果 STM32 上没接这根线，`IRQ` 这个"变量"根本不存在——你现在这行代码其实编译不过，或者读到一个悬空脚（电平随机）。

**两个方案，任选一个**：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 加一根线（推荐）** | 把模块 IRQ 接到 STM32 任意空闲脚（如 PB0），CubeMX 配成**上拉输入**或 **EXTI 下降沿** | 代码最贴近原驱动；可以用中断，不占 CPU | 要飞一根线 |
| **B. 不接 IRQ，改轮询** | 把 `while(IRQ==1)` 换成"反复读 STATUS，直到 TX_DS 或 MAX_RT 或超时" | 不用接线 | 占 CPU；比中断慢一点 |

**方案 B 的代码（不用 IRQ 也能跑）**：

```c
uint8_t SI24R1_WaitTxDone(uint32_t timeout_ms)
{
    uint32_t t0 = HAL_GetTick();
    while (HAL_GetTick() - t0 < timeout_ms) {
        uint8_t st = SI24R1_Read_Reg(STATUS);         /* P18 */
        if (st & (TX_DS | MAX_RT)) return st;         /* 成功或失败都算结束 */
    }
    return 0xFF;                                       /* 超时 */
}
```

> 注意：`TX_DS`/`MAX_RT` 的宏在 Si24R1 里是 `0x20`/`0x10`（**P18**，比 nRF24 右移一位）。

## 2. 逐项对照：原写法 → 你的工程写法

### 2.1 引脚操作（51 的 `sbit` → HAL）

**原来（51 或正点原子位带）**：

```c
sbit SCK = P1^0;        /* 51：直接绑到端口位 */
sbit CSN = P1^1;
#define SCK  PAout(5)   /* 或正点原子：位带操作 */

SCK = 0;                /* 直接赋值 */
CSN = 1;
```

**STM32 HAL 写法**：

```c
/* 用 CubeMX 生成的宏（main.h 里已定义） */
SI24R1_CSN(1);          /* 自己定义的宏，见下 */

/* 宏的实现 */
#define SI24R1_CSN(x)  HAL_GPIO_WritePin(SPI1_NSS_GPIO_Port, SPI1_NSS_Pin, \
                                         (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)
#define SI24R1_CE(x)   HAL_GPIO_WritePin(SP_EN_GPIO_Port, SP_EN_Pin, \
                                         (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)
```

**为什么要这么改（三个原因）**：

| 原因 | 说明 |
| --- | --- |
| ① 51 的端口是"固定地址 + 位寻址"，STM32 的 GPIO 是"寄存器 + 位掩码" | 51 能 `sbit` 一次绑定，STM32 必须写 `BSRR/BRR` 寄存器，HAL 帮你封装成 `WritePin` |
| ② 引脚必须先在 CubeMX 里配好模式 | 51 的引脚方向由硬件决定，STM32 的每个脚可以是输入/输出/复用/模拟，**不配就是浮空** |
| ③ 用宏包一层，换板子只改宏 | 以后引脚变了，只改两行宏，`.c` 里几十处调用一行不用动 |

### 2.2 数据类型（`u8` → `uint8_t`）

```c
u8  status;      /* ❌ 51 的 typedef，STM32 工程没有 */
uint8_t status;  /* ✅ 标准类型，stm32f1xx_hal.h 里有 */
```

`u8/u16/u32` 是 51 时代为省字打的简写，STM32 工程统一用 `stdint.h` 的类型（`uint8_t/uint16_t/uint32_t`）——这样跨平台、跨编译器都不会出错。

### 2.3 延时（`delay_us` → `HAL_Delay` / DWT）

| 场景 | 用什么 | 为什么 |
| --- | --- | --- |
| 毫秒级（上电 100ms） | `HAL_Delay(100)` | 手册 **P6**：上电延时 100ms |
| 微秒级（CE 保持 10us） | **DWT 延时** 或 `__NOP()` 循环 | `HAL_Delay` 最小 1ms，太粗 |

**CE 高电平至少要 10us**（手册 **P7 3.1.4**）。硬件 SPI 下 `Write_Buf` 本身就要几十微秒，所以通常**不用额外延时**；但如果你的 SPI 特别快（比如 1 字节只要 2us），就要补：

```c
SI24R1_CE(1);
for (volatile int i = 0; i < 100; i++) { __NOP(); }   /* 约 10us @72MHz */
```

### 2.4 SPI 收发（软件模拟 → 硬件 SPI）

**原来（软件模拟，逐位翻转）**：

```c
static u8 SPI_RW(u8 byte)
{
    u8 i, rx = 0;
    for (i = 0; i < 8; i++) {
        MOSI = (byte & 0x80) ? 1 : 0;   /* 摆最高位 */
        byte <<= 1;
        SCK = 1;                         /* 上升沿，从机采样 */
        rx = (rx << 1) | (MISO ? 1 : 0); /* 同时收一位 */
        SCK = 0;                         /* 下降沿，换下一位 */
    }
    return rx;
}
```

**STM32 硬件 SPI 写法（3 行）**：

```c
static uint8_t SI24R1_SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;
}
```

**你的 CubeMX 已经把 SPI1 配对了**（我从 `spi.c` 里读出来的）：

| 参数 | 你的值 | 对不对 |
| --- | --- | --- |
| Mode | `SPI_MODE_MASTER` | ✅ 主机 |
| Direction | `SPI_DIRECTION_2LINES` | ✅ 全双工 |
| DataSize | `SPI_DATASIZE_8BIT` | ✅ 8 位 |
| **CLKPolarity** | `SPI_POLARITY_LOW` | ✅ 模式 0 的一半 |
| **CLKPhase** | `SPI_PHASE_1EDGE` | ✅ 模式 0 的另一半 |
| NSS | `SPI_NSS_SOFT` | ✅ 片选自己控制（PA4） |
| BaudRatePrescaler | `SPI_BAUDRATEPRESCALER_8` | ✅ 72M/8 = **9MHz**（手册 P15 上限 10MHz） |
| FirstBit | `SPI_FIRSTBIT_MSB` | ✅ 高位先发 |

**结论：你的 SPI1 配置完全符合 Si24R1 要求，不用动。**

## 3. 移植四步（照着做，不跳）

### 第 1 步：把引脚集中到一个"端口文件"（10 分钟）

新建 `MDK-ARM/Interface/Int_SI24R1_Port.h`：

```c
#ifndef __INT_SI24R1_PORT_H__
#define __INT_SI24R1_PORT_H__

#include "main.h"
#include "spi.h"

/* ================= 你的板子引脚（改板子只改这一段） ================= */
#define SI24R1_CSN_PORT    SPI1_NSS_GPIO_Port     /* PA4 */
#define SI24R1_CSN_PIN     SPI1_NSS_Pin
#define SI24R1_CE_PORT     SP_EN_GPIO_Port        /* PA8：请确认是不是 CE */
#define SI24R1_CE_PIN      SP_EN_Pin

/* IRQ：目前没接。接了就把下面两行取消注释并改成实际引脚 */
//#define SI24R1_IRQ_PORT  GPIOB
//#define SI24R1_IRQ_PIN   GPIO_PIN_0
/* =================================================================== */

/* 操作宏：以后代码里只用这三个 */
#define SI24R1_CSN(x)  HAL_GPIO_WritePin(SI24R1_CSN_PORT, SI24R1_CSN_PIN, \
                                         (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)
#define SI24R1_CE(x)   HAL_GPIO_WritePin(SI24R1_CE_PORT, SI24R1_CE_PIN, \
                                         (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)

#ifdef SI24R1_IRQ_PIN
#define SI24R1_IRQ()   HAL_GPIO_ReadPin(SI24R1_IRQ_PORT, SI24R1_IRQ_PIN)
#endif

#endif
```

**为什么单独一个文件**：以后换板子（比如从 P01 换到 P02），只改这 6 行，`.c` 一行不动。这是"可移植"的具体做法。

### 第 2 步：改 SPI 原语（5 分钟）

把 `.c` 第 6~9 行的 `SPI_RW` 换成：

```c
static uint8_t SI24R1_SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;
}
```

然后把文件里所有 `SPI_RW(...)` 改成 `SI24R1_SPI_RW(...)`。

### 第 3 步：把 `CSN = 0/1`、`CE = 0/1` 全部替换（10 分钟）

| 原写法 | 新写法 |
| --- | --- |
| `CSN = 0;` | `SI24R1_CSN(0);` |
| `CSN = 1;` | `SI24R1_CSN(1);` |
| `CE = 0;` | `SI24R1_CE(0);` |
| `CE = 1;` | `SI24R1_CE(1);` |
| `SCK = 0;`（`Init` 里那行） | **删掉**（硬件 SPI 自动管 SCK） |
| `IRQ = 1;`（`Init` 里那行） | **删掉**（输入脚不能写） |
| `while(IRQ == 1);` | 用 1.3 的方案 A 或 B |

### 第 4 步：修 5 个编译问题（15 分钟）

| # | 位置 | 改法 |
| --- | --- | --- |
| 1 | `.h` 60/62 行 | `SI24R1_WRITE_REG` → `SI24R1_Write_Reg`；`SI24R1_READ_REG` → `SI24R1_Read_Reg` |
| 2 | `.c` 113~141 行 | `WRITE_REG` → `SI24R1_WRITE_REG` |
| 3 | `.h` 60~68 行 | `u8` → `uint8_t` |
| 4 | `.h` 72 行 | `Int_SI24R1_Init` ↔ `.c` 17 行 `SI24R1_Init`，统一名字 |
| 5 | `.c` 8 行 | `SPI_RW` 补完整（见第 2 步） |

## 4. 完整可编译版：`Int_SI24R1.c` 的骨架（移植后长这样）

```c
#include "Int_SI24R1.h"
#include "Int_SI24R1_Port.h"

uint8_t TX_ADDRESS[TX_ADR_WIDTH] = {0x0A,0x01,0x06,0x0E,0x01};

/* ---------- 第 1 层：SPI 原语（唯一碰硬件的地方） ---------- */
static uint8_t SI24R1_SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;
}

/* ---------- 第 0 层：上电静默 ---------- */
void Int_SI24R1_Init(void)
{
    HAL_Delay(100);              /* 手册 P6：上电延时 100ms */
    SI24R1_CSN(1);               /* 不选中 */
    SI24R1_CE(0);                /* 关闭收发，回 Standby（P7） */
}

/* ---------- 第 2 层：寄存器读写 ---------- */
uint8_t SI24R1_Write_Reg(uint8_t reg, uint8_t value)
{
    uint8_t status;
    SI24R1_CSN(0);
    status = SI24R1_SPI_RW(reg);       /* 命令，同时收回 STATUS（P14） */
    SI24R1_SPI_RW(value);              /* 数据 */
    SI24R1_CSN(1);
    return status;
}

uint8_t SI24R1_Read_Reg(uint8_t reg)
{
    uint8_t value;
    SI24R1_CSN(0);
    SI24R1_SPI_RW(reg);                /* 读命令 = 地址本身 */
    value = SI24R1_SPI_RW(0x00);       /* 空转字节，骗出数据 */
    SI24R1_CSN(1);
    return value;
}

uint8_t SI24R1_Write_Buf(uint8_t reg, const uint8_t *pBuf, uint8_t bytes)
{
    uint8_t status, i;
    SI24R1_CSN(0);
    status = SI24R1_SPI_RW(reg);
    for (i = 0; i < bytes; i++) SI24R1_SPI_RW(pBuf[i]);
    SI24R1_CSN(1);
    return status;
}

uint8_t SI24R1_Read_Buf(uint8_t reg, uint8_t *pBuf, uint8_t bytes)
{
    uint8_t status, i;
    SI24R1_CSN(0);
    status = SI24R1_SPI_RW(reg);
    for (i = 0; i < bytes; i++) pBuf[i] = SI24R1_SPI_RW(0x00);
    SI24R1_CSN(1);
    return status;
}

/* ---------- 纯命令（FLUSH / NOP 用） ---------- */
void SI24R1_Cmd(uint8_t cmd)
{
    SI24R1_CSN(0);
    SI24R1_SPI_RW(cmd);
    SI24R1_CSN(1);
}

/* ---------- 第 3 层：模式配置 ---------- */
void SI24R1_RX_Mode(void)
{
    SI24R1_CE(0);                                                     /* P7 */
    SI24R1_Write_Buf(SI24R1_WRITE_REG + RX_ADDR_P0, TX_ADDRESS, TX_ADR_WIDTH);
    SI24R1_Write_Reg(SI24R1_WRITE_REG + EN_AA,     0x01);             /* P17 */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + EN_RXADDR, 0x01);             /* P17 */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + RF_CH,     40);               /* 2440MHz */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + RX_PW_P0,  TX_PLOAD_WIDTH);   /* P19 */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + RF_SETUP,  0x0F);             /* 2M/7dBm */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + CONFIG,    0x0F);             /* RX+CRC16 */
    SI24R1_Write_Reg(SI24R1_WRITE_REG + STATUS,    0xFF);             /* 清标志 */
    SI24R1_CE(1);                                                     /* 开始监听 */
}
```

> 注意：这份骨架**只演示移植手法**，你原来的 `TX_Mode / RxPacket / TxPacket` 按同样方法替换宏即可，逻辑不用动。

## 5. 改了有什么用（5 条，按重要性）

| # | 收益 | 具体数字/效果 |
| --- | --- | --- |
| 1 | **能编译、能跑** | 原代码在你工程里 `u8` 未定义、`SCK` 宏不存在、`IRQ` 悬空——**根本过不了编译** |
| 2 | **SPI 快 10 倍** | 软件 SPI 约 1MHz（32 字节 ≈ 300us）；硬件 SPI 9MHz（≈ 30us）。收 100 包/秒时，CPU 占用从 3% 降到 0.3% |
| 3 | **不拖累 FreeRTOS 其他任务** | 你现在有电源、电机、LED 三个任务。SPI 慢 → 接收任务占 CPU 久 → 电机任务抖动 |
| 4 | **换板子只改 6 行** | 引脚全集中在 `Int_SI24R1_Port.h`，换 P02 遥控器时不用重写驱动 |
| 5 | **能调试** | 用逻辑分析仪能直接看到 SPI 波形（软件 SPI 也能，但硬件 SPI 波形更规整，一眼看出对错） |

**反过来，如果不改会怎样**：

- 编译报一堆 `u8` / `SCK` 未定义
- 就算你把 `SCK` 定义成宏硬凑出来，软件 SPI 在 72MHz 下速度也上不去
- `while(IRQ == 1)` 读一个没配置的引脚 → 行为随机，可能一上电就卡死
- 以后引脚一改，`Int_SI24R1.c` 里几十处全要动

## 6. 移植常见错误对照表（12 条，都是真实踩过的）

| # | 现象 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 编译报 `u8` 未定义 | 没 `typedef` | 全改 `uint8_t` |
| 2 | 编译报 `SCK` 未定义 | 51 的 `sbit` 宏 | 改 `HAL_GPIO_WritePin` |
| 3 | 读寄存器全 `0xFF` | MISO 没接 / 没配成输入 | CubeMX 里 PA6 配 `SPI1_MISO` |
| 4 | 读寄存器全 `0x00` | SPI 模式错（应是模式 0） | CPOL=Low + CPHA=1Edge |
| 5 | 写进去读不回 | 片选 PA4 一直是低（NSS 配错） | NSS 必须 `Software`，PA4 手工控制 |
| 6 | 能读能写但收不到 | 地址/频道/速率/长度不一致 | 四个值两端都打印出来对 |
| 7 | 发送永远 MAX_RT | 没接 ACK / 对方没进 RX / `RX_ADDR_P0 ≠ TX_ADDR` | **P10 4.2.1**：发送端 P0 地址必须等于自己的 TX 地址 |
| 8 | 一上电就卡死 | `while(IRQ)` 死等 | 加超时或改轮询 |
| 9 | 改配置没生效 | CE=1 时写寄存器 | **P14**：只在 Shutdown/Standby/Idle-TX 写 |
| 10 | 数据长度不对 | `RX_PW_P0` 与发送字节数不一致 | 静态长度两端对齐 |
| 11 | 偶尔丢包 | RX FIFO 只存 3 包（**P8**） | 提高读取频率 |
| 12 | 距离特别近 | 功率配成 0dBm 甚至更低 | `RF_SETUP=0x0F`（+7dBm，**P18**） |

## 7. 移植后自检（4 步，每步看输出）

```c
/* 1. 读 CONFIG —— 预期 0x08 左右 */
Debug_Printf("CONFIG=0x%02X\r\n", SI24R1_Read_Reg(CONFIG));

/* 2. 写读回 RF_CH —— 预期 40 */
SI24R1_Write_Reg(SI24R1_WRITE_REG + RF_CH, 40);
Debug_Printf("RF_CH=%d\r\n", SI24R1_Read_Reg(RF_CH));

/* 3. 进接收模式，读 STATUS —— 预期 RX_P_NO=0x0E（FIFO 空） */
SI24R1_RX_Mode();
Debug_Printf("STATUS=0x%02X\r\n", SI24R1_Read_Reg(STATUS));

/* 4. 两块板对发 —— 发送端返回 0x20 表示成功 */
```

| 卡在哪 | 说明 | 查哪里 |
| --- | --- | --- |
| 第 1 步就失败 | SPI 物理层 | PA4/PA5/PA6/PA7 接线、SPI 模式、`hspi1` 是否 `MX_SPI1_Init()` 过 |
| 第 2 步失败 | 命令拼错 | 是不是忘了 `+ SI24R1_WRITE_REG`（0x20） |
| 第 3 步异常 | 配置顺序 | `CE=0` 有没有先执行 |
| 第 4 步失败 | 双方参数 | 地址/频道/速率/长度；ACK 的 P0 地址 |
