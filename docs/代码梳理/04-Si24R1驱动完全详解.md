## 1. 先认识这颗芯片

### 1.1 它到底是什么

Si24R1 是一颗 **2.4GHz 无线收发芯片**（不是模块，是芯片；你手上那块板子 = 芯片 + 16MHz 晶振 + 天线匹配 + 排针）。

它的定位：**替你做"无线"这件事**。你只要通过 SPI 把数据丢给它，它就自动打包、加地址、加 CRC、调制、发射；接收时它自动解调、比对地址、校验 CRC、去重、回 ACK，然后把干净的数据放进 FIFO 等你来取。

**所以你写的驱动，本质上只有四件事**：

```
配寄存器（告诉它怎么工作） → 写 FIFO（让它发） → 读 FIFO（收数据） → 看状态（判断成败）
```

### 1.2 关键参数（手册第 1 页 + 第 7 章）

| 参数 | 数值 | 对你的意义 |
| --- | --- | --- |
| 频段 | 2.4GHz ISM | 免授权，但和 WiFi/蓝牙同频段，会互相干扰 |
| 调制 | GFSK / FSK | — |
| 速率 | **2Mbps / 1Mbps / 250Kbps** | 越快越省时间、距离越短 |
| 最大发射功率 | **+7dBm** | 比 nRF24L01（0dBm）强，实测空旷 100~200m 量级（取决于天线） |
| 接收灵敏度 | -83dBm @2Mbps | 越低越能收弱信号 |
| 供电 | 1.9 ~ 3.6V | **3.3V 标准，别接 5V** |
| 数字 IO 电压 | 1.9 ~ 5.25V | 好消息：**IO 可以直接接 5V 单片机**（如 51） |
| 关断电流 | 1uA | 电池设备的关键 |
| 待机电流 | 15uA | 比关断大 15 倍 |
| 接收电流 | 15mA @2Mbps | 一直开着很费电 |
| 发射电流 | 12mA @0dBm | 峰值更高 |
| 晶振 | 16MHz ±60ppm | 板载，不用管 |
| SPI 最高 | **10MHz** | 你的 HAL 配 9MHz 正好 |
| 启动时间 | ≤130us | 从待机到能收发的切换时间 |
| 封装 | QFN20 / COB | — |

### 1.3 引脚（手册第 2 章）

| 引脚 | 方向 | 作用 | 你的接法 |
| --- | --- | --- | --- |
| CE | 输入 | **芯片使能**：高电平才工作（收发） | 任意 GPIO（建议 PB0） |
| CSN | 输入 | **SPI 片选**，低有效 | 任意 GPIO（建议 PA4） |
| SCK | 输入 | SPI 时钟 | SPI1_SCK = PA5 |
| MOSI | 输入 | SPI 数据输入 | SPI1_MOSI = PA7 |
| MISO | 输出 | SPI 数据输出 | SPI1_MISO = PA6 |
| IRQ | 输出 | 中断，**低有效**，可屏蔽 | 任意 GPIO 输入（建议 PB1） |
| VDD / VSS | 电源 | 1.9~3.6V | 3.3V + 0.1uF 去耦 |
| XI / XO | 晶振 | 16MHz | 板载 |
| RFP / RFN | 射频 | 天线差分 | 板载巴伦/天线 |
| VDD_PA | 输出 | 内部 PA 电源（+1.8V） | 接去耦电容，**不要外接负载** |
| IREF | 模拟 | 基准电流 | 接精密电阻到地（板载） |

**你只需要关心前 6 个引脚**，后面都是板载电路的事。

### 1.4 五种工作模式（手册 3.1，这节必须懂）

芯片内部有状态机，**不是"上电就能收发"**：

```
          ┌──────────────┐
          │   Shutdown   │  1uA，寄存器/FIFO 内容保留，SPI 仍可读写
          └──────┬───────┘
      PWR_UP=1   │   ↑ PWR_UP=0
                 ▼   │
          ┌──────────────┐
          │   Standby    │  15uA，晶振工作，1.5~2ms 时钟稳定
          └──┬────────┬──┘
   CE=1,     │        │   CE=1, PRIM_RX=1
   PRIM_RX=0 │        │
             ▼        ▼
      ┌──────────┐  ┌────────┐
      │ Idle-TX  │  │   RX   │  15mA，持续监听
      └────┬─────┘  └────────┘
   FIFO有数据│CE=1
           ▼
      ┌──────────┐
      │    TX    │  12mA，发一包（CE 高 ≥10us 触发）
      └──────────┘
```

**四条必须记住的时间**：

| 切换 | 时间 | 出处 |
| --- | --- | --- |
| 上电 → 可用 | **100ms**（上电延时） | 3.1 图注 + 第 7 章 |
| PWR_UP=1 → Standby | **1.5~2ms**（晶振稳定） | 3.1.2 |
| Standby/Idle-TX → RX 或 TX | **120~130us** | 3.1.3 / 3.1.5 |
| CE 高脉冲宽度（触发发射） | **≥10us** | 3.1.4 |

**实践含义**：

- 刚上电不要立刻配寄存器，先 `HAL_Delay(100)`
- 从"待机"切到"接收"要 130us 才真正开始收 —— 如果对方发完一包就走，你可能刚好错过
- 发一包至少要把 CE 拉高 10us，软件 SPI 天然满足；**硬件 SPI 太快时，拉高后加 `__NOP()` 或 `HAL_Delay(1)` 更稳**

**还有一条隐藏规矩（手册 5.2 注）**：

> **只能在 Shutdown、Standby、Idle-TX 模式下配置寄存器。**

也就是说：`CE=1` 正在接收时，你写寄存器可能被忽略。**改配置前先把 CE 拉低**——你代码里 `RX_Mode()` / `TX_Mode()` 开头都写了 `CE=0`，这是对的。

### 1.5 空中的数据包长什么样（手册 4.1）

你写进 FIFO 的 32 字节，并不是直接发到空中的。芯片会自动给它套壳：

```
┌────────┬──────────┬──────────────┬────────────┬──────┐
│ 前导码  │   地址    │  包控制字 9bit │  负载数据   │ CRC  │
│ 1~2字节 │ 3/4/5字节 │ 长度6+PID2+NAK1│ 0~32字节   │ 1/2B │
└────────┴──────────┴──────────────┴────────────┴──────┘
   自动      你配的      自动生成        你写的      自动
```

| 字段 | 谁决定 | 说明 |
| --- | --- | --- |
| 前导码 | 芯片自动 | 接收端自动去掉，用户看不见 |
| 地址 | 你写进 `TX_ADDR` | **接收端必须与 `RX_ADDR_Px` 相同** |
| 长度 | 写 FIFO 时自动 | 静态长度时 = `RX_PW_Px`；动态时 = 包里的 6bit |
| PID | 芯片自动（每发新包 +1） | 接收端用它判断"是不是重发的同一包" |
| NO_ACK | 由你用的命令决定 | `W_TX_PAYLOAD_NOACK` 会置 1 |
| CRC | 芯片自动 | 8bit 或 16bit，由 `CRCO` 决定 |

**两个致命细节**：

1. **地址最高字节不能是** `0xFF / 0x00 / 0xA5 / 0x5A / 0xAA / 0x55`（手册 4.1）。这些是前导码/同步字的模式，会干扰同步。你代码里的地址 `{0x0A,0x01,0x06,0x0E,0x01}`，最高字节（最后写入的那个）= `0x01`，**安全**。
2. **地址是"LSByte 先写"**（手册 6 节 0x0A 说明）。你的数组 `[0]=0x0A` 就先写 `0x0A`，所以 MSB 是 `[4]=0x01`。

## 2. SPI 通信层：唯一需要懂硬件的地方

### 2.1 四根线 + 主机/从机

| 线 | 谁驱动 | 方向 | 作用 |
| --- | --- | --- | --- |
| SCK | STM32 | 主 → 从 | 打节拍，芯片跟着走 |
| MOSI | STM32 | 主 → 从 | 主机发命令/数据 |
| MISO | **Si24R1** | 从 → 主 | 芯片回数据 |
| CSN | STM32 | 主 → 从 | 低 = 选中这颗芯片，高 = 结束 |

**记住三个"单向性"**：

- 时钟永远由主机产生，芯片不会自己开始通信
- CSN 是**单片机拉、芯片听**，芯片不能反拉
- 只有 MISO 是芯片"说"的线

### 2.2 命令表（手册表 5-1，抄下来当字典）

| 命令 | 命令字（二进制） | 数据字节 | 作用 |
| --- | --- | --- | --- |
| `R_REGISTER` | `000A AAAA` = `0x00｜addr` | 1~5 | 读寄存器 |
| `W_REGISTER` | `001A AAAA` = `0x20｜addr` | 1~5 | 写寄存器（仅 Shutdown/Standby/Idle-TX） |
| `R_RX_PAYLOAD` | `0110 0001` = `0x61` | 1~32 | 从 RX FIFO 取数据（取出即删除） |
| `W_TX_PAYLOAD` | `1010 0000` = `0xA0` | 1~32 | 写 TX FIFO（ACK 模式） |
| `FLUSH_TX` | `1110 0001` = `0xE1` | **0** | 清空 TX FIFO |
| `FLUSH_RX` | `1110 0010` = `0xE2` | **0** | 清空 RX FIFO |
| `REUSE_TX_PL` | `1110 0011` = `0xE3` | **0** | 重发上一次的包（不能配合 FLUSH 用） |
| `R_RX_PL_WID` | `0110 0000` = `0x60` | 1 | 读收到的包长度（动态长度用） |
| `W_ACK_PAYLOAD` | `1010 1PPP` = `0xA8｜pipe` | 1~32 | 把数据塞进 ACK 回给对方 |
| `W_TX_PAYLOAD_NOACK` | `1011 0000` = `0xB0` | 1~32 | 写 TX FIFO（不等 ACK，需 EN_DYN_ACK） |
| `NOP` | `1111 1111` = `0xFF` | 0 | 空操作，专门用来读 STATUS |

**三句话记住命令的分类**：

1. **读寄存器**：地址本身（`0x00~0x1F`）
2. **写寄存器**：地址 `｜0x20`（`0x20~0x3F`）
3. **FIFO/特殊命令**：独立编号（`0x60/0x61/0xA0/0xA8/0xB0/0xE1/0xE2/0xE3/0xFF`），**不加 0x20**

### 2.3 一帧 SPI 的形状（四种）

```
① 读寄存器（2 字节）
CSN ‾\_____________________/‾
MOSI --- 命令(0x00|addr) --- 空转(0x00/0xFF) ---
MISO --- STATUS(8bit) ------ 寄存器值(8bit) ----
                              ↑ 这才是你要的值

② 写寄存器（2 字节）
CSN ‾\_____________________/‾
MOSI --- 命令(0x20|addr) --- 数据 ---
MISO --- STATUS ------------ xx -----

③ 写多字节（1+N 字节，CSN 全程低）
MOSI --- 命令 --- D0 --- D1 --- D2 ... ---
                  ↑ 连续写进 addr, addr+1, addr+2 ...

④ 纯命令（1 字节，无数据）
MOSI --- FLUSH_TX(0xE1) ---
CSN 低→高，芯片执行
```

### 2.4 时序参数（手册表 5-1，第 15 页）

| 参数 | 最小 | 含义 | 你需要注意什么 |
| --- | --- | --- | --- |
| `Fsck` | 0 | 最高 **10MHz** | HAL 分频后别超过 |
| `Tdc` | 2ns | 数据建立时间 | 软件 SPI 天然满足 |
| `Tdh` | 2ns | 数据保持时间 | 同上 |
| `Tcsd` | 42ns | CSN 到数据有效 | 硬件 SPI 若很快，CSN 拉低后等一下 |
| `Tcl/Tch` | 40ns | 时钟低/高电平宽度 | 对应 12.5MHz 上限 |
| `Tcc` | 2ns | CSN 到第一个 SCK | 软件 SPI 足够 |
| `Tcwh` | 50ns | **两次操作之间 CSN 至少高 50ns** | 连续读写之间别死循环狂刷 |

**结论**：软件 SPI（微秒级）对 10MHz 上限来说慢得绰绰有余；硬件 SPI 配 9MHz 也在范围内。真正要小心的是 **CSN 之间至少 50ns 的空闲**——连续两个 `Write_Reg` 之间不要零延时。

### 2.5 最关键的一条：MISO 第一字节**永远**是 STATUS

手册 5.1 原文：

> 每一次 SPI 操作，MISO 输出的第一字节为状态寄存器的值，之后通过命令来确定是否输出值（不输出为高阻态）。

这就是你代码里 `status = SPI_RW(reg);` 的**全部理由**：

- 你发命令的那 8 个时钟，芯片在 MISO 上**同时**吐 STATUS
- 之后如果命令是"读"，才会继续吐寄存器值；如果是"写"，MISO 变高阻（读到的值无意义）

**应用**：想只看状态、不想读寄存器？发 `NOP(0xFF)` 就行——这也是 `SI24R1_Read_Reg` 为什么写 `SPI_RW(0)` 作为空转字节。

### 2.6 软件 SPI vs 硬件 SPI（两种都给你）

| 对比 | 软件 SPI（逐位翻转 GPIO） | 硬件 SPI（SPI 外设） |
| --- | --- | --- |
| 速度 | 约 1MHz 级别 | 最高 10MHz（你配 9MHz） |
| CPU 占用 | 高（每字节 8 次循环） | 低（DMA 更低） |
| 引脚要求 | 任意 GPIO | 必须用 SPI 复用引脚 |
| 调试难度 | 容易（能看到每一位） | 中等（要看波形） |
| 适合 | 学习、引脚冲突、时序排查 | 产品、大数据量 |

**软件版原语**（学原理用）：

```c
static void SPI_RW_Soft(uint8_t *buf, uint16_t len)
{
    for (uint16_t i = 0; i < len; i++) {
        uint8_t b = buf[i];
        for (uint8_t bit = 0; bit < 8; bit++) {
            HAL_GPIO_WritePin(MOSI_PORT, MOSI_PIN, (b & 0x80) ? GPIO_PIN_SET : GPIO_PIN_RESET);
            b <<= 1;
            HAL_GPIO_WritePin(SCK_PORT, SCK_PIN, GPIO_PIN_SET);      /* 上升沿：从机采样 */
            if (HAL_GPIO_ReadPin(MISO_PORT, MISO_PIN)) b |= 0x01;    /* 同时收一位 */
            HAL_GPIO_WritePin(SCK_PORT, SCK_PIN, GPIO_PIN_RESET);    /* 下降沿：换下一位 */
        }
        buf[i] = b;
    }
}
```

**硬件版原语**（产品用，你代码里第 6~9 行就该是这个）：

```c
static uint8_t SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;                       /* 收到的那个字节 = STATUS 或寄存器值 */
}
```

## 3. 寄存器层：手册第 6 章逐条翻译

### 3.1 寄存器全景表（先看这张，再逐个看）

| 地址 | 名字 | 作用 | 复位默认 |
| --- | --- | --- | --- |
| 0x00 | CONFIG | **总开关**：上电/收发/CRC/中断屏蔽 | 0x08 |
| 0x01 | EN_AA | 哪些管道自动回 ACK | 0x3F |
| 0x02 | EN_RXADDR | 哪些管道能收 | 0x03 |
| 0x03 | SETUP_AW | 地址宽度 3/4/5 字节 | 0x03（5B） |
| 0x04 | SETUP_RETR | 重发延时 ARD + 次数 ARC | 0x07 |
| 0x05 | RF_CH | 频道 0~125 | 0x02 |
| 0x06 | RF_SETUP | **速率 + 功率** + 测试模式 | 0x0E |
| 0x07 | STATUS | **状态/中断标志**（只读为主，写 1 清） | 0x0E |
| 0x08 | OBSERVE_TX | 丢包数 + 重发数（调试神器） | 0x00 |
| 0x09 | RSSI | 1 位信号强度 | 0x00 |
| 0x0A | RX_ADDR_P0 | 管道 0 地址（5 字节全） | 0xE7E7E7E7E7 |
| 0x0B | RX_ADDR_P1 | 管道 1 地址（5 字节全） | 0xC2C2C2C2C2 |
| 0x0C~0x0F | RX_ADDR_P2~P5 | 管道 2~5 地址（**只有最低字节**） | C3/C4/C5/C6 |
| 0x10 | TX_ADDR | 发射地址（5 字节） | 0xE7E7E7E7E7 |
| 0x11~0x16 | RX_PW_P0~P5 | 各管道**静态**负载长度 1~32 | 0x00 |
| 0x17 | FIFO_STATUS | 收发队列满/空 | 0x11 |
| 0x1C | DYNPD | 哪些管道用**动态长度** | 0x00 |
| 0x1D | FEATURE | 动态长度/ACK 载荷/NO_ACK 总开关 | 0x00 |

> 记忆法：**0x00 开关、0x01~0x04 规则、0x05~0x06 射频、0x07~0x09 状态、0x0A~0x10 地址、0x11~0x16 长度、0x17 队列、0x1C~0x1D 高级功能**。

### 3.2 CONFIG（0x00）—— 最重要的一字节

| 位 | 名字 | 默认 | 作用 |
| --- | --- | --- | --- |
| 7 | Reserved | 0 | 保留，写 0 |
| 6 | `MASK_RX_DR` | 0 | 1 = 屏蔽"收到数据"中断（IRQ 不响应） |
| 5 | `MASK_TX_DS` | 0 | 1 = 屏蔽"发送完成"中断 |
| 4 | `MASK_MAX_RT` | 0 | 1 = 屏蔽"重发超限"中断 |
| 3 | `EN_CRC` | **1** | 1 = 开 CRC（EN_AA 非 0 时必须为 1） |
| 2 | `CRCO` | 0 | 0 = CRC 8 位；1 = CRC 16 位 |
| 1 | `PWR_UP` | 0 | 0 = 关断；1 = 上电 |
| 0 | `PRIM_RX` | 0 | 0 = 发射模式；1 = 接收模式（**只能在 Shutdown/Standby 下改**） |

**常用组合**（直接抄）：

| 用途 | 值 | 说明 |
| --- | --- | --- |
| 接收模式，2 字节 CRC，全中断开启 | **0x0F** | = 0000 1111（你代码用的） |
| 发射模式，2 字节 CRC，全中断开启 | **0x0E** | = 0000 1110 |
| 关断（省电） | 0x0C / 0x00 | PWR_UP=0 |
| 接收但不想要 IRQ 打断 | 0x7F / 0x4F | 屏蔽对应位 |

**坑**：

- 只改 `PRIM_RX` 时不要"读-改-写"整个 CONFIG，因为它同时控制 CRC 和中断屏蔽，容易改坏
- `PRIM_RX` 在 RX 模式（CE=1）下**改不动**，必须 CE=0

### 3.3 EN_AA / EN_RXADDR —— 管道的两个开关

**EN_AA（0x01，默认 0x3F）**：对应管道要不要"收到就自动回 ACK"

```
bit5..bit0 = ENAA_P5 ... ENAA_P0
你写 0x01 → 只给管道 0 开自动应答
```

**EN_RXADDR（0x02，默认 0x03）**：哪些管道**能收**

```
bit5..bit0 = ERX_P5 ... ERX_P0
你写 0x01 → 只开管道 0
```

**两者区别（最常被搞混）**：

| 寄存器 | 管什么 | 不开会怎样 |
| --- | --- | --- |
| `EN_RXADDR` | **能不能收到**这个管道的数据 | 地址配了也收不到 |
| `EN_AA` | 收到后**要不要自动回 ACK** | 能收到，但对方永远 TX_DS 失败（收不到 ACK） |

**实战原则**：

- 单向传输（只要收到就行）→ `EN_AA=0`，省事、省时
- 要可靠传输 → 双方都开 `EN_AA`

### 3.4 SETUP_AW（0x03）—— 地址宽度

| `AW[1:0]` | 含义 |
| --- | --- |
| 00 | 错误值（别用） |
| 01 | 3 字节 |
| 10 | 4 字节 |
| **11** | **5 字节（默认，你用的）** |

**不用改它**——默认 5 字节，和你 `TX_ADR_WIDTH=5` 一致。

> 如果想省空口时间（3 字节比 5 字节省 2 字节），可以改成 3 字节，但**地址冲突概率上升**，而且**双方必须一致**。

### 3.5 SETUP_RETR（0x04）—— 重发策略

| 位 | 名字 | 含义 |
| --- | --- | --- |
| 7:4 | `ARD` | 自动重发**间隔**：0000=250us，0001=500us，… 1111=4000us（每档 +250us） |
| 3:0 | `ARC` | 最大重发**次数**：0000=关闭，0001=1 次，… 1111=15 次 |

**你代码用的 `0x0A`**：

- 高 4 位 `0000` → ARD = 250us（加上硬件开销约 250+86us）
- 低 4 位 `1010` = 10 → 最多重发 10 次

**总耗时估算**：10 次 × (250us + 86us) ≈ 3.4ms，最坏情况下 `TxPacket` 会阻塞这么久。

**怎么选**：

| 场景 | ARD | ARC | 理由 |
| --- | --- | --- | --- |
| 遥控（实时性优先） | 250us | 2~3 | 失败就丢，别拖 |
| 参数配置（可靠性优先） | 1000us | 10~15 | 慢点无所谓，务必送到 |
| 单向广播 | — | 0（关闭） | 不要 ACK |

### 3.6 RF_CH（0x05）—— 频道

```
实际频率 = 2400MHz + RF_CH
你写 40 → 2440MHz
```

- 范围 `0~125` → `2400~2525MHz`
- 间隔 1MHz
- **WiFi 信道 1/6/11 分别在 2412/2437/2462MHz**，2440 附近相对干净，但**不绝对**

**实用建议**：量产时用"上电扫频"选最干净的信道（扫 RSSI 或统计 PLOS_CNT），比死写一个频道强得多。

### 3.7 RF_SETUP（0x06）—— 速率与功率（★最容易配错）

| 位 | 名字 | 说明 |
| --- | --- | --- |
| 7 | `CONT_WAVE` | 1 = 持续载波（**产测专用**，平时必须 0） |
| 6 | Reserved | 0 |
| 5 | `RF_DR_LOW` | 与 bit3 组合决定速率 |
| 4 | `PLL_LOCK` | **必须为 0**（保留字） |
| 3 | `RF_DR_HIGH` | 同上 |
| 2:0 | `RF_PWR` | 发射功率 |

**速率编码（这是 Si24R1 与 nRF24L01 的差异点，务必看表）**：

| `RF_DR_LOW`,`RF_DR_HIGH` | 速率 |
| --- | --- |
| 0,0 | 1Mbps |
| 0,1 | **2Mbps** |
| 1,0 | **250Kbps** |
| 1,1 | 保留（别用） |

**功率编码（8 档）**：

| `RF_PWR[2:0]` | 功率 |
| --- | --- |
| 111 | **+7dBm**（最大） |
| 110 | +4dBm |
| 101 | +3dBm |
| 100 | +1dBm |
| 011 | 0dBm |
| 010 | -4dBm |
| 001 | -6dBm |
| 000 | -12dBm |

**你代码用的 `0x0F`** = `0000 1111`：

- bit5=0, bit3=1 → **2Mbps**
- bit2:0 = `111` → **+7dBm**
- 和注释"2Mbps、7dBm"完全一致 ✅

> ⚠️ 很多网上 Si24R1 代码是从 nRF24L01 抄的，功率注释写"0dBm"、编码写 `0x06`（1Mbps+0dBm），**能跑但距离差一截**。想拉距离，先看这里。

### 3.8 STATUS（0x07）—— 全项目最容易错的一个字节（★重要）

**Si24R1 的实际位定义（手册第 18 页）**：

| 位 | 名字 | 掩码 | =1 表示 |
| --- | --- | --- | --- |
| 7 | Reserved | — | 永远 0 |
| 6 | **RX_DR** | **0x40** | RX FIFO 里有数据（收到包了） |
| 5 | **TX_DS** | **0x20** | 发送完成（ACK 模式下 = 收到对方 ACK） |
| 4 | **MAX_RT** | **0x10** | 重发次数超限，这包失败 |
| 3:1 | `RX_P_NO` | 0x0E | 数据来自哪个管道；**7 = RX FIFO 空** |
| 0 | `TX_FULL` | 0x01 | TX FIFO 满 |

**而 nRF24L01+ 的位定义是**：

| 位 | 名字 | 掩码 |
| --- | --- | --- |
| 7 | RX_DR | 0x80 |
| 6 | TX_DS | 0x40 |
| 5 | MAX_RT | 0x20 |
| 4:1 | RX_P_NO | 0x1E |
| 0 | TX_FULL | 0x01 |

**差一位！** 因为 Si24R1 把 bit7 留空了。

**这就是为什么**：

- 你的 `Int_SI24R1.h` 里 `RX_DR 0x40 / TX_DS 0x20 / MAX_RT 0x10` —— **对 Si24R1 完全正确** ✅
- 如果你从网上抄 nRF24L01 的 `0x80/0x40/0x20` 直接用在 Si24R1 上 → **收不到数据、发送永远"失败"**，而且编译不报错，极难查 ❌

**清零方式：写 1 清零**

```c
/* 清掉"收到数据"和"发送完成"两个标志 */
SI24R1_Write_Reg(SI24R1_WRITE_REG + STATUS, 0x60);   /* 0x40 | 0x20 */
```

你代码里的写法是"读出当前值再写回去"：

```c
state = SI24R1_Read_Reg(STATUS);
SI24R1_Write_Reg(WRITE_REG + STATUS, state);   /* 置位的位写 1 → 被清掉 */
```

这个写法能工作（把读到的 1 原样写回去），但**会把 RX_P_NO 那几位也写回去**——那几位是只读，写入被忽略，所以无害。更干净的做法是只写你要清的掩码。

### 3.9 OBSERVE_TX（0x08）—— 调试神器，多数人不知道

| 位 | 名字 | 含义 |
| --- | --- | --- |
| 7:4 | `PLOS_CNT` | 丢包计数（0~15，改 RF_CH 会归零） |
| 3:0 | `ARC_CNT` | 当前包重发了多少次 |

**怎么用（实战价值很高）**：

```c
uint8_t obs = SI24R1_Read_Reg(OBSERVE_TX);
uint8_t lost = (obs >> 4) & 0x0F;    /* 最近丢了多少包 */
uint8_t retry = obs & 0x0F;          /* 这一包重发了几次 */

if (lost > 5) {
    /* 链路很差：换频道 / 降速率 / 检查天线 */
}
```

- **`ARC_CNT` 一直大于 0** → 链路勉强能用，但随时会断 → 该降速率（2M→1M）或换频道
- **`PLOS_CNT` 增长快** → 空口环境太脏或距离太远

**这就是"用数据说话"，比凭感觉判断信号好不好强太多。**

### 3.10 RSSI（0x09）—— 1 位信号强度

| 位 | 含义 |
| --- | --- |
| 0 | 1 = 接收信号 **> -60dBm**；0 = 小于 |

**注意**：

- 只有 1 位，**不能测具体 dBm**（要精确测得上频谱仪）
- 只在接收模式有效；收到有效包后自动更新，或从 RX 切到 Standby 时更新
- 误差 ±5dBm，随温度漂

**能用来干什么**：

- 粗略判断"对方离我近不近"
- 失控保护：连续 N 包 RSSI=0 → 判定飞远/遮挡 → 触发返航逻辑
- 产测：贴脸测试确认发射正常

### 3.11 地址寄存器（0x0A~0x10）—— 管道设计的核心（★重点）

| 寄存器 | 字节数 | 说明 |
| --- | --- | --- |
| `RX_ADDR_P0` | **5** | 管道 0 完整地址 |
| `RX_ADDR_P1` | **5** | 管道 1 完整地址 |
| `RX_ADDR_P2~P5` | **1** | **只有最低字节**，高 4 字节强制等于 P1 的高 4 字节 |
| `TX_ADDR` | **5** | 发射目标地址 |

**这个设计带来的硬约束（非常多项目在这里翻车）**：

> 管道 2~5 的地址 = `P1 的高 4 字节` + `各自的最低字节`。

举例（手册图 4-6）：

```
P1 = B1 C2 D3 E4 F5     （5 字节）
P2 = B1 C2 D3 E4 DE     （只写最低字节 DE）
P3 = B1 C2 D3 E4 78
P4 = B1 C2 D3 E4 C9
P5 = B1 C2 D3 E4 34
```

**所以"1 拖 6"的星型网络，那 6 个从机的地址必须共享前 4 个字节**。如果你想让 6 个从机地址完全不同 → **做不到**，只能用 P0 + P1 两个"全地址管道"，P2~P5 只能改最后一个字节。

**另外**：

- `TX_ADDR` 必须等于对方某个 `RX_ADDR_Px`
- 如果需要收 ACK，**自己的 `RX_ADDR_P0` 必须等于自己的 `TX_ADDR`**（因为对方的 ACK 是发到这个地址的）
- 地址 MSB 不能用那 6 个禁值

### 3.12 RX_PW_Px（0x11~0x16）—— 静态负载长度

| 值 | 含义 |
| --- | --- |
| 0 | 该管道未使用 |
| 1~32 | 每包固定接收这么多字节 |

**关键**：静态长度模式下，**收方 `RX_PW_Px` 必须等于发方每包写的字节数**。

- 你代码：`TX_PLOAD_WIDTH = 32`，收发都 32 → 一致 ✅
- 如果发 5 字节、收方配 32 → 收到的数据后 27 字节是垃圾/旧数据，前 5 字节才是真的
- 如果发 32、收方配 5 → 只收到前 5 字节，后 27 字节丢失（且 FIFO 可能错位）

**想"变长"就得用动态长度（DPL）**，见 3.14。

### 3.13 FIFO_STATUS（0x17）—— 队列状态

| 位 | 名字 | 含义 |
| --- | --- | --- |
| 6 | `TX_REUSE` | 重发模式标志（用了 `REUSE_TX_PL` 才置位） |
| 5 | `TX_FULL` | TX FIFO 满 |
| 4 | `TX_EMPTY` | TX FIFO 空（默认 1） |
| 1 | `RX_FULL` | RX FIFO 满 |
| 0 | `RX_EMPTY` | RX FIFO 空（默认 1） |

**重要事实（手册 3.1.5）**：

> **RX FIFO 最多存 3 包**，满了以后新来的包**自动丢弃**。

**实践含义**：

- 接收端必须**及时取数据**，否则丢包（而且丢了不报错，你只会发现"数据少了"）
- 判断"有没有数据"用 `STATUS.RX_DR`（更快）或 `FIFO_STATUS.RX_EMPTY`
- 批量读时：读一包 → 看 `RX_EMPTY` → 还有就继续读

### 3.14 FEATURE（0x1D）/ DYNPD（0x1C）—— 三个高级功能的总开关

| FEATURE 位 | 名字 | 打开后能干什么 |
| --- | --- | --- |
| 2 | `EN_DPL` | **动态负载长度**：每包长度可不同 |
| 1 | `EN_ACK_PAY` | **ACK 带载荷**：回 ACK 时顺便捎数据（双向通信神器） |
| 0 | `EN_DYN_ACK` | **NO_ACK 命令**：发完就走，不等确认 |

**DYNPD（0x1C）**：哪几个管道用动态长度（bit0~bit5 对应管道 0~5）

**动态长度的用法**：

```c
/* 双方都要开 */
SI24R1_Write_Reg(SI24R1_WRITE_REG + FEATURE, 0x04);   /* EN_DPL=1 */
SI24R1_Write_Reg(SI24R1_WRITE_REG + DYNPD, 0x01);     /* 管道 0 用动态 */

/* 接收端读长度 */
uint8_t len = SI24R1_Read_Reg(R_RX_PL_WID);           /* 0x60 */
if (len > 32) { SI24R1_Write_Reg(FLUSH_RX, 0xFF); }   /* 长度异常要清 FIFO */
```

> 坑：开 DPL 后 `RX_PW_Px` 就不起作用了；而且**双方必须都开**，只有一边开会收到乱码长度。

## 4. 协议层：ARQ 是怎么"自己"跑起来的

### 4.1 ACK 模式（默认，最常用）

```
发送端                          接收端
  │  写 FIFO（W_TX_PAYLOAD）
  │  CE=1 ──────────────────────► 收到包
  │                               ├ 地址匹配？
  │                               ├ CRC 对？
  │                               ├ PID 是不是重复？
  │                               └ 存进 RX FIFO → RX_DR=1 → IRQ 拉低
  │  ◄──────────── ACK ───────────┤ 自动回 ACK
  ├ 收到 ACK → TX_DS=1
  └ 没收到  → 等 ARD → 重发（最多 ARC 次）→ 还没 → MAX_RT=1
```

**三个决定成败的配置**：

| 配置 | 在哪 | 错了会怎样 |
| --- | --- | --- |
| 对方地址 = 我的 `TX_ADDR` | `RX_ADDR_Px` | 收不到 |
| 我的 `RX_ADDR_P0` = 我的 `TX_ADDR` | 接收 ACK 用 | 对方收到了，但我永远收不到 ACK → 一直重发 → MAX_RT |
| 双方 `EN_AA` 都开 | `EN_AA` | 一方关闭 → 另一方永远等不到 ACK |

### 4.2 NO_ACK 模式（广播/高频数据流）

```
发送端：W_TX_PAYLOAD_NOACK → 发完立刻 TX_DS=1，不管对方
接收端：收到就存，不回复 ACK
```

**适合**：

- 遥控摇杆数据（丢了就丢了，下一帧马上来）
- 一对多广播
- 对延迟极敏感的场景（省掉 ACK 的往返时间）

**代价**：**没有可靠性保证**，丢了你也不知道。

### 4.3 动态负载长度（DPL）

- 每包长度 0~32 可变
- 发送端：写多少发多少
- 接收端：用 `R_RX_PL_WID(0x60)` 问长度
- 前提：双方 `FEATURE.EN_DPL=1` + `DYNPD` 对应管道使能

**用途**：协议里既有 4 字节遥测、又有 32 字节参数包时，不用全都发 32 字节。

### 4.4 PID + CRC：自动去重

芯片自动给每个新包加 PID（0~3 循环），接收端发现"PID 相同 + CRC 相同"就判定为重发包，**丢弃并重新回 ACK**。

**你要知道的后果**：

- 你不需要自己做"重复包过滤"
- 但 PID 只有 2 位（4 种），**连续丢 4 包以上就可能误判**

### 4.5 ACK PAYLOAD（双向通信的神技，值得单独学）

**场景**：遥控器 → 飞机（发摇杆），飞机 → 遥控器（回传电量/姿态）。

常规做法是"飞机再开一个发射流程"，费时。**ACK PAYLOAD 让飞机的数据搭着 ACK 回去**：

```
遥控器                          飞机
  │ 发摇杆数据 ─────────────────► 收到
  │                                ├ 把"电量 80%"塞进 TX FIFO（W_ACK_PAYLOAD）
  │  ◄──── ACK + 电量 80% ─────────┤ 回 ACK 时带上
  ├ TX_DS=1 且 RX_DR=1
  └ 从 RX FIFO 读出"电量 80%"
```

**配置**：

```c
/* 双方 */
Feature |= EN_ACK_PAY | EN_DPL;      /* ACK 载荷必须配动态长度 */

/* 接收端（飞机）：把要回的数据塞进某个管道的 ACK 队列 */
uint8_t telemetry[4] = {80, 12, 3, 0};
SI24R1_Write_Buf(0xA8 | 0, telemetry, 4);   /* W_ACK_PAYLOAD，管道 0 */
```

**收益**：一次往返完成"下行 + 上行"，延迟减半，功耗更低。做遥控器项目几乎必用。

## 5. 你的驱动逐行解剖

### 5.1 文件职责与分层

| 文件 | 职责 | 不该放什么 |
| --- | --- | --- |
| `Int_SI24R1.h` | 名词表：命令、寄存器地址、位掩码、函数声明 | 任何实现 |
| `Int_SI24R1.c` | 动作：SPI 原语、寄存器读写、模式配置、收发 | 业务逻辑（该放 Application） |
| `Core/Src/spi.c` | CubeMX 生成的 SPI1 初始化 | 手改（会被重新生成覆盖） |

```
Application（任务里调 TxPacket/RxPacket）
        ↓
Interface（Int_SI24R1.c：4 个读写 + 2 个模式 + 2 个收发）
        ↓
HAL（HAL_SPI_TransmitReceive / HAL_GPIO_WritePin）
        ↓
硬件（SPI1 + GPIO）
```

### 5.2 第 0 层：地址数组

```c
uint8_t TX_ADDRESS[TX_ADR_WIDTH] = {0x0A,0x01,0x06,0x0E,0x01};
```

- **全局一份**，发送端当 `TX_ADDR`、接收端当 `RX_ADDR_P0`，天生一致
- `[0]` 是最低字节（LSByte），**先写**；`[4]=0x01` 是最高字节（MSB）
- MSB 避开了 `0xFF/0x00/0xA5/0x5A/0xAA/0x55` → 安全
- 想改地址：**两端一起改**，且最好有规律（如 `0x0A,0x01,0x06,0x0E,机号`）

### 5.3 第 1 层：`SPI_RW`（你这里还没写完）

**应有形态**：

```c
static uint8_t SPI_RW(uint8_t byte)
{
    uint8_t rx = 0;
    HAL_SPI_TransmitReceive(&hspi1, &byte, &rx, 1, 100);
    return rx;
}
```

**四个参数的含义**：

| 参数 | 传什么 | 为什么 |
| --- | --- | --- |
| `&hspi1` | SPI 句柄 | CubeMX 生成在 `spi.c` 里 |
| `&byte` | 要发的 1 字节 | 发送缓冲 |
| `&rx` | 接收缓冲 | 收到的字节（= STATUS 或寄存器值） |
| `1` | 长度 | 一次 1 字节 |
| `100` | 超时 ms | 防止死等 |

**为什么必须 `TransmitReceive` 而不是 `Transmit`**：SPI 是"发一个收一个"，需要给接收留缓冲，否则收到的字节被丢弃，你就读不到寄存器值。

### 5.4 第 2 层：四个读写函数

| 函数 | 字节序列 | 返回 | 关键点 |
| --- | --- | --- | --- |
| `Write_Reg(reg,val)` | 命令 → 数据 | STATUS | 命令 = `0x20｜addr` |
| `Write_Buf(reg,pBuf,n)` | 命令 → n 个数据 | STATUS | **CSN 全程低** |
| `Read_Reg(reg)` | 命令 → 空转 | 寄存器值 | 命令 = `addr`（不带 0x20） |
| `Read_Buf(reg,pBuf,n)` | 命令 → n 次空转 | STATUS | 空转字节内容随意（0x00/0xFF） |

**为什么"命令只发一次"**：手册说 `W_REGISTER` 后面可以跟 1~5 个数据字节，芯片会自动往 `addr, addr+1, ...` 写。地址是 5 字节连续寄存器，所以必须用 `Write_Buf` 一次写完——分 5 次写会被当成 5 帧，**地址就写乱了**。

**你代码里已经做对的地方**：

- `CSN = 0/1` 严格包住整个函数 ✅
- `Write_Buf` 里 `*pBuf++` 先取值再挪指针 ✅
- `Read_Buf` 用 `pBuf[byte_ctr] = SPI_RW(0)` 逐字节收 ✅

### 5.5 第 3 层：`RX_Mode` / `TX_Mode` 逐行

**`RX_Mode()` 的 9 个动作（顺序不能乱）**：

| 步 | 代码 | 为什么必须在这 |
| --- | --- | --- |
| 1 | `CE = 0` | 进入 Standby，**只有这样才能改寄存器** |
| 2 | 写 `RX_ADDR_P0` | 先定"听谁" |
| 3 | 写 `EN_AA = 0x01` | 打开管道 0 自动回 ACK |
| 4 | 写 `EN_RXADDR = 0x01` | 打开管道 0 的接收开关 |
| 5 | 写 `RF_CH = 40` | 频道必须与发送端一致 |
| 6 | 写 `RX_PW_P0 = 32` | 静态长度，必须与发送端字节数一致 |
| 7 | 写 `RF_SETUP = 0x0F` | 2Mbps + 7dBm |
| 8 | 写 `CONFIG = 0x0F` | **上电 + 接收模式 + CRC 16 位** |
| 9 | `CE = 1` | 真正开始监听（130us 后生效） |

**第 8 步为什么在最后**：因为 `CONFIG` 一写，芯片就按新配置工作了。如果提前上电，芯片会用旧配置收一会儿，可能有垃圾数据进 FIFO。

**`TX_Mode()` 与 `RX_Mode()` 的差异（只需记 5 条）**：

| 项目 | RX_Mode | TX_Mode | 原因 |
| --- | --- | --- | --- |
| `TX_ADDR` | 不写 | **写** | 发送端要知道"喊谁" |
| `RX_ADDR_P0` | 写 | **也写** | 要收 ACK（ACK 是发到这个地址的） |
| `SETUP_RETR` | 不配 | `0x0A` | 只有发送需要重发策略 |
| `CONFIG` | `0x0F` | `0x0E` | 唯一区别是 `PRIM_RX` |
| `CE` | `=1` 持续监听 | `=0`（交给 TxPacket） | 发射是"脉冲式"触发 |

### 5.6 第 4 层：`RxPacket` / `TxPacket`

**`RxPacket` 的 4 步**：

```c
state = Read_Reg(STATUS);            /* ① 看报告 */
Write_Reg(STATUS, state);            /* ② 写 1 清标志 */
if (state & RX_DR) {                 /* ③ 有数据？ */
    Read_Buf(0x61, rxbuf, 32);       /* ④ 读 32 字节，读完 FIFO 自动少一包 */
    return 0;                        /*    0 = 成功 */
}
return 1;                            /*    1 = 没数据 */
```

**返回值约定**：`0` 成功、`1` 没数据（**和很多库相反**，别写反）。

**`TxPacket` 的时序（最关键）**：

```c
CE = 0;                              /* ① 必须关，CE=1 时不能写 FIFO */
Write_Buf(0xA0, txbuf, 32);          /* ② 塞 32 字节进 TX FIFO */
CE = 1;                              /* ③ 触发发射（≥10us 高电平） */
while (IRQ == 1);                    /* ④ 等 IRQ 拉低（⚠️ 无超时 = 可能死等） */
state = Read_Reg(STATUS);            /* ⑤ 读结果 */
Write_Reg(STATUS, state);            /*    清标志 */
if (state & MAX_RT) { FLUSH_TX; return MAX_RT; }  /* ⑥ 失败 */
if (state & TX_DS)  { return TX_DS; }             /* ⑦ 成功 */
return 0xFF;
```

**几个必须知道的细节**：

1. `CE=1` 后芯片进入 TX，发完一包后：`CE=1` 且 FIFO 空 → 自动回 **Idle-TX**（不是 Standby）
2. `MAX_RT` 置位后**必须先清标志**，否则不能发下一包（你代码清了 ✅）
3. `while (IRQ == 1)` 在"对方不在/天线没接/地址错"时会**永远卡住** → 必须加超时
4. 发完不拉低 `CE` 也能跑（下次开头会拉低），但明确 `CE=0` 更符合手册

## 8. 一定要记住的 12 条（其余全部可查）

```
①  SPI 是主机打时钟，从机被动跟着；一次 8 个时钟换 1 字节（同时收发）
②  CSN 低 = 选中芯片，高 = 结束；一帧必须用 CSN 包住
③  第 1 字节是命令：读=地址，写=地址|0x20，FIFO 命令是独立编号
④  读寄存器要跟一个"空转字节"骗时钟；写寄存器跟的是数据
⑤  MISO 第一字节永远是 STATUS —— 这是"顺手拿状态"的来源
⑥  改寄存器只能在 Shutdown/Standby/Idle-TX；PRIM_RX 只能在 Shutdown/Standby 改
⑦  CONFIG 的 bit0 决定收/发；bit1 是上电
⑧  STATUS（Si24R1）：RX_DR=0x40、TX_DS=0x20、MAX_RT=0x10、TX_FULL=0x01 —— 和 nRF24L01 差一位！
⑨  地址两端必须相同；地址 MSB 禁用 6 个特殊值
⑩  管道 0/1 是完整 5 字节地址，管道 2~5 只能改最低字节
⑪  RX FIFO 只存 3 包，不及时读就丢
⑫  发一包 = CE 拉低 → 写 FIFO → CE 拉高 ≥10us → 等 IRQ/超时
```

**为什么是这 12 条**：它们决定了"能不能通"和"通了之后稳不稳"。其余（地址表、掩码表、编码表）都是查一下的事。

## 9. 管道（Pipe）到底有什么用：6 种实战玩法

### 9.1 基础概念：管道 = 带过滤器的信箱

- 芯片有 **6 个管道**（P0~P5）
- 每个管道有：**自己的地址**、**自己的开关**（EN_RXADDR）、**自己的 ACK 开关**（EN_AA）、**自己的长度**（RX_PW_Px）
- 收到的包先比对地址，**匹配哪个管道就存哪个管道**，`STATUS.RX_P_NO` 会告诉你"这包从哪个管道来的"

**关键约束（再强调）**：管道 0、1 有完整 5 字节地址；**管道 2~5 只能设最低字节**，高 4 字节强制等于管道 1。

### 9.2 玩法一：1 拖 6 星型网络（手册 4.2.4 官方场景）

```
        从机1 (地址 A5A5A5A5A5) ──┐
        从机2 (B1C2D3E4DE) ──────┤
主机 ── 从机3 (B1C2D3E4F5) ──────┤  主机：P0=A5.., P1=B1C2D3E4F5,
        从机4 (B1C2D3E478) ──────┤        P2=B1C2D3E4DE, P3=..78,
        从机5 (B1C2D3E4C9) ──────┤        P4=..C9, P5=..34
        从机6 (B1C2D3E434) ──────┘
```

**用途**：一个遥控器带 6 个执行器；一个网关收 6 个传感器。

**注意**：从机 2~6 的地址前 4 字节必须相同（`B1C2D3E4`），只有最后 1 字节不同。

### 9.3 玩法二：遥控 + 遥测"双管道"（最实用）

```
遥控器 → 飞机：管道 0（发摇杆）
飞机   → 遥控器：管道 1（发遥测：电量/姿态/信号）
```

- 两个管道用不同地址，互不干扰
- 各自 `RX_PW_Px` 可以设不同长度（摇杆 8 字节、遥测 16 字节）
- 比"一个管道混着发"好处：**接收端一眼知道这包是什么类型**（看 `RX_P_NO`）

```c
uint8_t pipe = (SI24R1_Read_Reg(STATUS) >> 1) & 0x07;
switch (pipe) {
    case 0: /* 摇杆数据 */ break;
    case 1: /* 遥测数据 */ break;
}
```

### 9.4 玩法三：ACK PAYLOAD 做"伪全双工"

遥控器发一包 → 飞机回 ACK 时捎带状态。**一次往返，双向数据**。

**省下的时间** ≈ 一整个发射周期（含 ACK 等待），遥控延迟能减半。

### 9.5 玩法四：频道当"组"，地址当"机"

```
RF_CH = 40 → A 组（比如 1 号机组）
RF_CH = 50 → B 组
组内：地址区分不同飞机
```

**好处**：多组同场（比赛/教学）不互相干扰；换组只改一个字节。

### 9.6 玩法五：广播信标（NO_ACK）

主机用 `W_TX_PAYLOAD_NOACK` 周期性发"我在、我的频道是 40、我的地址是 XX"，所有从机都能收（把从机管道地址设成广播地址）。

**用途**：设备发现、配对、心跳。

### 9.7 玩法六：跳频抗干扰

```
每 10ms 换一个频道（RF_CH 40→45→50→…）
双方按同一个伪随机序列跳
```

- 遇到 WiFi 干扰只是"某一跳丢了"，不会整段断
- 配合 `OBSERVE_TX.PLOS_CNT` 统计丢包，动态调整跳频表

## 11. 换别的芯片怎么办：通用五步法

这套方法对 **任何 SPI/I2C 外设** 都适用（MPU6050、VL53L4CD、OLED、Flash…）：

```
第 1 步 接线表：电源/地/通信线/控制线，每根线接哪
第 2 步 通信原语：读一个字节、写一个字节（只跟总线有关）
第 3 步 读一个已知寄存器：能读到正确值 = 线对了、时序对了  ★最关键
第 4 步 配置 + 最小功能：只做一件事（发一包 / 读一次 ID）
第 5 步 封装业务接口：给上层留 Send/Recv/Read/Write
```

**第 3 步是分水岭**：90% 的人跳过它直接写完整驱动，然后"不通"时完全不知道错在哪。

**换芯片时的检查清单**：

| 检查项 | 为什么 |
| --- | --- |
| 供电电压范围 | 3.3V 还是 5V，超压烧片 |
| 总线类型与模式 | SPI 模式 0/1/2/3、I2C 地址 |
| 最高时钟 | 超了会读错 |
| 寄存器地址宽度 | 8 位还是 16 位（有些芯片要 2 字节地址） |
| 是否需要片选/使能脚 | CE/CS/RST |
| 有没有"忙"标志 | 需要轮询等待 |
| 上电时序 | 有的芯片要求先 RST 再配置 |
| 中断脚极性 | 高有效还是低有效 |

```
【模式】RX: CONFIG=0x0F + CE=1      TX: CONFIG=0x0E + FIFO + CE脉冲
【STATUS】RX_DR=0x40  TX_DS=0x20  MAX_RT=0x10  TX_FULL=0x01  (Si24R1!)
【频道】2440MHz = RF_CH 40
【速率/功率】RF_SETUP=0x0F → 2Mbps + 7dBm
【必须一致】地址 / 频道 / 速率 / 长度
【改配置前】CE=0
【发一包】CE=0 → 写FIFO → CE=1(≥10us) → 等IRQ(带超时) → 读STATUS
【调试】OBSERVE_TX 看丢包与重发；FIFO_STATUS 看队列；RSSI 看强弱
```

## 附录 B：故障排查表（按现象查）

| 现象 | 最可能的原因 | 先查什么 |
| --- | --- | --- |
| 读寄存器全是 0x00 / 0xFF | SPI 没通 | CSN/MISO 接线、SPI 模式、片选是否真的拉低 |
| 读 CONFIG 不是 0x08 附近 | 没上电/上电时间不够 | 加 100ms 延时；确认 PWR_UP |
| 能读能写，但收不到 | 地址/频道/速率/长度不一致 | 把两边的 4 个值都打印出来对 |
| 收不到且 EN_AA 开着 | 自己 `RX_ADDR_P0` ≠ `TX_ADDR` | 发送端必须能收到 ACK |
| 发送永远 MAX_RT | 对方没在收 / 地址错 / 天线没接 | 先确认对方 RX_DR 有没有置位 |
| 发送成功但对方没数据 | 对方 FIFO 满了没读 | 检查读取频率、FIFO_STATUS |
| 偶尔丢包 | 距离/干扰/速率太高 | 降速率 2M→1M，换频道 |
| 数据长度不对 | 静态长度不匹配 | `RX_PW_Px` 与发送字节数对齐 |
| 收到的数据错位 | 上次没读完 FIFO | 每次读完 FLUSH_RX |
| 程序卡死 | `while(IRQ)` 死等 | 加超时 |
| 一上电就死机 | 供电不足/去耦不够 | 3.3V 电源加 10uF+0.1uF |
| 距离特别近 | RF_SETUP 配成 0dBm 或更低 | 改 `RF_PWR=111`（+7dBm） |
| 数据偶尔整包丢失 | RX FIFO 只存 3 包 | 提高读取频率或加中断 |
| 多机互相串数据 | 地址/频道相同 | 用管道或频道分组 |
| 换电池后不工作 | 电压低于 1.9V | 检查电源 |
